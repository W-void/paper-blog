## 🧭 方向性归纳

### 1. 工业落地：大一统架构的"冲突治理"功夫

本周工业论文的共同姿势是"合"，但真正的看点在"怎么合才不打架"。

Lazada 的 [LazUnirec](https://arxiv.org/abs/2611.32590) 把召回和排序合成一个 Transformer，直指统一式推荐的两大痛点：单一 backbone 下两任务梯度方向冲突，且冲突时没有判断"听谁的"的依据。解法分三层：注意力层用 LoRA 做"共享底座 + 任务私货"，FFN 层用任务自适应稀疏 MoE 分家，再靠不确定性估计仲裁梯度冲突——谁的更新方向更可靠就听谁的，另加排序→召回的知识蒸馏做跨任务迁移。这是近期少见的完整工业级统一架构报告，已在 Lazada 多场景线上部署。

WSDM 2027 收录的 [DCDN](https://arxiv.org/abs/2611.27514) 干的事更基础：DCN/DCNv2 的交叉层只会做"乘法"（非负整数次幂多项式），现实里最有用的比率类特征（CTR、like rate）本质是"除法"，过去只能人工算好喂进去。DCDN 在交叉层加了条除法分支，理论上把可表达函数刻画为多元 Laurent 多项式（带符号次数 [-K, K+1]），补齐了表达力缺口。落地结果干脆利落：整类人工比率特征全部删除，输入特征数减少 40.1%，线上 A/B 分享率 +16.26%、点赞 +3.25%（均统计显著），已在短视频生产排序栈全量部署，代码开源。

网易云音乐的 [CAMAR](https://arxiv.org/abs/2611.33628) 处理的是多域负迁移：把用户表示因果分解为 domain-invariant 与 domain-specific 分量，跨域只让"不变的那部分"流动，配合残差量化从预训练文本/视觉/音频特征生成 semantic-ID 嵌入打通行为稀疏域的语义耦合，再用迁移网络为不活跃域插补用户表示。网易云音乐在线 A/B 三个域全胜，是多域推荐少见的规模化落地案例。

阿里 [OneQuery](https://arxiv.org/abs/2611.33653)（WSDM 2027 Findings）则把跨境电商查询理解的语言识别、纠错、翻译、打标四个串联模块，重构为一个受 schema 约束的"序列到结构"生成任务，配三阶段渐进训练 + 多任务 RL 对齐，在 AliExpress 拿到线上收益——电商检索链路"大一统生成化"趋势的又一例证。

### 2. 生成式推荐：从"快"到"可证明的快"

上周 GR 的关键词是"上线"，本周声量小但角度独特：[SIDECAR](https://arxiv.org/abs/2611.32855) 把大模型推理里的投机解码搬进了 SID 生成式检索。现有 beam search 每个请求要串行跑 L 次模型，慢，而且模型不自信时检索质量悄悄变差、你还不知道。SIDECAR 先拿草稿候选，用一次 tree-attention 调用给所有草稿打分，过程中对每个未探索的 SID 前缀计算概率上界：草稿若包含精确 top-K 则直接给出证书（certify），否则 branch-and-bound 只扩展仍可能改变输出的 trie 分支，最坏 L 次调用内完成认证。它输出的不只是结果，还有一个 1+δ 因子明确告诉你"离精确有多远"。在同等资源预算下与 beam search 严格可比，优势在于可早停 + 近似程度始终可解释。当 GR 进入生产环境，"可认证的近似"可能比"平均更快"更值钱。

### 3. 评估与可信：离线指标"照妖镜"续集

评测反思连续第二周成为主线，本周两篇各有杀伤力。

[Sequencing Shortcuts](https://arxiv.org/abs/2611.33240) 给教育推荐的离线评估泼了盆冷水：教育场景里"下一步学什么"大多是平台决定的（老师布置、按掌握度出题），一个完全不看用户历史、只会照着"平台套路"猜下一步的傻瓜模型，竟能达到最强个性化方法 95% 的准确率（中位数）；号称很强的大模型排序器（0.5B~7B）换上"符合课程结构的难负样本"后表现掉到接近随机。更扎心的是模拟实验里，离线准确率甚至把"学习者需求的 oracle"排在"平台模仿者"之下。作者提出 syllabus-aware 评估清单并开源工具包——对所有依赖隐式反馈做离线评估的场景都成立。

TMLR 已发表的 [UQ 基准](https://arxiv.org/abs/2611.33036) 则盯上了 LLM 排序器的"心里有没有底"问题：现有不确定性量化方法出处不同、阶段不同，根本没法公平比。作者搭了一个 fixed-ranking 基准，8 种异构 UQ 信号统一为监控器，在 4 个推荐数据集 × 2 个 LLM 骨干上测。关键发现：UQ 方法排序对 backbone 敏感（换骨干就换人）；排序对齐信号 Top10Mass 在检测"top-10 有没有错"上最稳；标量信号难以识别控制变量间的真实差异，扰动排序稳定性类信号反而更强。

### 4. 表示、融合与迁移：多基座时代的"接线术"

三篇论文共同回答了同一个问题：基座模型快速迭代的时代，推荐系统怎么接？

[UF2O](https://arxiv.org/abs/2611.31951) 的关键观察是：naive 拼接多个基座模型（LLM、视觉、图模型）的表示比单用一个强不了多少——因为"哪个基座对哪类用户更有用"存在系统性差异。解法是给每个基座维护独立推荐视图，在分数层按用户自适应融合，异构基座之间完全不需要对齐表示空间，4 数据集 × 4 基座比最强融合基线最高提升 7%，代码开源。

[ERA](https://arxiv.org/abs/2611.26919) 解决换 embedding 模型的冷启动迁移：只对余弦最远点采样选出的一小撮锚点文档花新模型编码预算，训一个轻量适配器（流形对齐损失 + 正交正则）做"新模型 → 旧索引"映射，再用路由器把少数难查询升级到新 encoder。端到端延迟从约 160ms 降到 38-86ms，Arguana 上 nDCG@10 相对提升至 35%。同日的 [RELAY](https://arxiv.org/abs/2611.31882) 也是同一战场的姊妹篇：学习投影让同一查询向量同时给新旧两版文档打分，增量换模型免重编码。

轻量化侧，[MELODI](https://arxiv.org/abs/2611.31940) 把"相似度信息"和"身份信息"解耦，并证明了一个漂亮的结论：只要相似度算子对历史参数线性，"先算相似再池化"和"先池化再算相似"等价——于是可以采用更廉价的 pool-then-similarity 形式。工业级数据集上精度不输 target-aware 基线，CPU 实测延迟更低。

### 5. 个性化生成与用户主权

Adobe 的 [StylePrism](https://arxiv.org/abs/2611.27211) 把个性化长文生成里的"风格提取"从隐式变显式：定义 7 大类 28 个风格维度，先从用户旧文提取带引文证据的"风格档案"，再按档案起草、按档案修订两轮，LongLaMP 三个任务 × 三个 LLM 上 27 组对比赢 25 组（平均 +10.2%）。消融结论很有意思：档案当"修订时的 check-list"有效，单独当写作依据反而全输——价值在于推理时的自我批判信号，而非替代样本本身。

[Agentic Waterfall](https://arxiv.org/abs/2611.34407) 把推荐的主动权从算法手里还给用户：用户显式指令驱动 LLM 控制器沿意图"瀑布式"发现信息，持久化用户状态随浏览行为持续演化，形成"意图→检索→反馈→状态更新"闭环，还贡献了配套数据集和 replay 评估协议（传统基准持平，自有数据集最高相对提升 16.1%）。从"被动投喂"到"用户主权推荐"的范式探索。

WSDM 2027 主会的 [MKGE](https://arxiv.org/abs/2611.34436) 把用户偏好从"绑死单个商品"解放到"可复用的语义概念"：从商品图文归纳概念词表（"复古风""机械键盘"），把交互历史 grounding 到概念节点上，不同商品的证据围绕同一偏好概念积累，偏好变得可迁移、可解释，对低活跃用户尤其有效，六个指标全面超越 CF/KG/多模态/LLM 基线，代码与知识图谱开源。

## 🔍 横向对比

**统一化浪潮的真正门槛是冲突治理。** 本周 LazUnirec（召回+排序）、CAMAR（多域）、OneQuery（四个查询理解子任务）都在做"合"，但没有一篇是粗暴共享参数：LazUnirec 靠 LoRA/MoE/不确定性仲裁，CAMAR 靠因果分解只让不变分量跨域，OneQuery 靠 schema 约束 + 渐进训练缓解梯度冲突。DCDN 看似另一条线（特征交叉结构创新），实则同宗——它把人工特征工程里"人替模型做的组合"（比率）交还给网络，也是一种"统一"。可以概括为：**大一统的收益大家都看得见，论文的价值在于各自给出了一套可复用的"不打架"机制**。

**三篇"接线术"论文拼出了多基座时代的完整工具箱。** UF2O 回答"多个基座怎么组合"（score-level 用户自适应融合），ERA/RELAY 回答"基座换了旧向量怎么办"（适配器投影/兼容表示）。共同答案是：**放弃表示层对齐，在分数层或投影层做文章**——工程上更便宜，且天然支持异构。对正在多基座、频繁换模型的团队，这一组几乎是现成的选型参考。

**评测反思连续两周扩圈，且开始指向 LLM 本身。** 上周的 KuaiRecV2/INTENT/IntentTwin 打的是"基准数据集"，本周 Sequencing Shortcuts 打的是"反馈生成机制"（平台行为 ≠ 用户需求），UQ 基准打的是"LLM 排序器的可靠性无法默认信任"。两周一共六篇论文从不同角度汇聚到同一结论：**离线指标的上涨可能来自捷径而非能力，而 LLM 加入后"看起来很强"的捷径反而更多**。Sequencing Shortcuts 里 LLM ranker 加难负样本掉到随机，与 UQ 基准里"换骨干结论就翻转"互相印证——在 LLM 排序进入生产之前，可靠性与不确定性度量是必答题，不是加分项。
