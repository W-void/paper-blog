# Beyond Item IDs: Scaling Short-Form-Video Recommendation via Semantic-Native Long Sequence Modeling

- **日期**：2026-06-09
- **来源**：https://arxiv.org/pdf/2606.07546
- **作者**：Ruixiao Sun, Diego Uribe Mora, Zhimeng Jiang, Yuanzhen Lin, Jiarui Wang, Yuening Li, Danfeng Guo, Zhizhong Chen, Chuan He, Liang Liu
- **发表**：SIGIR '26, July 20–24, 2026, Melbourne, VIC, Australia

---

## 缺口

短视频推荐的用户行为序列早已突破千级（L > 1000），但工业系统在这个尺度上被两道瓶颈同时卡住。第一道是**表示瓶颈**：传统的原子 Video ID 把每个视频当作一个独立符号，ID 之间没有语义关联，embedding 表随语料规模线性膨胀，新视频（冷启动）拿不到有意义的 embedding。第二道是**计算瓶颈**：标准 Transformer 的 self-attention 是 O(L²) 复杂度，在严格的工业延迟约束下根本扛不住 L=2000 的序列。

已有方案对这两个瓶颈的处理都是"缺一半"：SIM/TWIN 等两阶段方案通过启发式过滤或聚类绕开了计算瓶颈，但引入了信息损失和复杂的离线预计算；PLUM/TRM 等开始探索 Semantic ID，但它们和超长序列建模之间的协同效应从未被验证过。**没有人在十亿用户规模上同时解决这两个瓶颈**。

## 增量

这篇论文在 Google 的十亿用户短视频平台上，用"深度截断 Bigram Semantic ID + Global-Aware Compressed Transformer（时间折叠+全局查询）"的组合拳，同时消灭了表示瓶颈和计算瓶颈，把序列从 L=800 推到 L=2000，满足观看时长 +1.42%，满足观看次数 +1.08%，embedding 参数减少 38%，序列模块峰值内存降低 92.2%。

## 核心机制

整个框架分为两个正交的组件：

**组件一：Semantic-Native 表示（Bigram SID）。** 上游 RQ-VAE 把每个视频压缩成一串层级离散编码 (c₁, c₂, ..., c_D)。对序列里的视频，只保留前两层（c₁, c₂），展平成一个整数 ID_seq = c₁ · |V| + c₂。这相当于只取到"子垂类"粒度（如"游戏-沙盒" vs "游戏-射击"），让 embedding 表大小被码本容量封顶（不再随语料线性增长）。候选侧（target item）和非序列侧保留更多层级做精细匹配——这是一种非对称粒度策略。

**组件二：Global-Aware Compressed Transformer。** 分两步处理超长序列：

1. **时间折叠（Temporal Folding）**：把序列 (L, d) 按窗口 k 拆成 (L/k, k·d)。k 个相邻 token 直接拼接成一个"超级 token"——零参数、无损、纯 reshape。这把注意力的序列长度从 L 降到 L/k，复杂度从 O(L²) 降到 O((L/k)²)。同时 feature 维度变成 k·d，"超级 token"内部的 k 个交互被内化为特征维度上的相关性，交给后续的 FFN 去建模。

2. **全局查询融合（Global Query Token）**：在压缩后的序列前拼接一个可学习的 Global Query Token。它不用任何用户画像初始化——纯随机起步，逼注意力机制完全从动态交互中学习全局表示。同时它充当"attention sink"（吸收低熵无关信号，稳定训练）。最终输出用 Unified Masked Mean Pooling 把全局 token 和序列 token 一起加权平均。

```
输入序列 X ∈ R^(L×d)
     │
     ▼
┌─────────────────────────────────┐
│  Temporal Folding (k=4)          │
│  (L, d) → (L/4, 4d)            │
│  零参数 reshape                  │
└─────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────┐
│  Prepend Global Query Token      │
│  G_init ∈ R^(Ng × d)           │
│  拼接 → (L/4 + Ng, 4d)         │
└─────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────┐
│  Standard Transformer Layers     │
│  O((L/4)²) 复杂度              │
│  feature dim = 4d → 局部依赖    │
└─────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────┐
│  Unified Masked Mean Pooling     │
│  全局 + 序列 → u_final          │
└─────────────────────────────────┘
```

## 白话核喻

把你的完整刷视频历史想象成一条几千帧的长胶片。

传统方案给每帧贴一个唯一编号（Video ID），就像给每帧分配一个独立门牌号。门牌号之间没有任何地理关系——门牌号 12345 和 12346 可能一个在北京一个在巴黎。新拍的帧因为还没有被注册过门牌号，系统完全认不出它。

这篇论文做了两件事：

**换门牌号为邮政编码。** 不给每帧唯一编号，只标注它的"省+市"（Bigram SID = 粗垂类 + 子垂类）。上海的所有帧共享"31"开头的编码，新帧只要知道自己在哪个城市就能立刻获得语义——不需要等系统"学会"一个全新的门牌号。邮政编码的总数是有限的（码本容量），不随街道数量膨胀。

**拼帧为镜头再分析。** 不是一帧一帧看那几千帧胶片（O(L²) 的比较成本），而是每 4 帧拼成一个"镜头"，然后在镜头之间做比较。镜头数量缩到原来的 1/4，比较成本降到 1/16，而每个镜头内部 4 帧的信息都保留在其特征里。同时放一张空白纸条在胶片头——它没有任何预设立场，逼你看完所有镜头才决定"你整体想看什么"。

## 关键概念（费曼讲解）

### 概念一：Residual Quantized VAE（RQ-VAE）与深度截断 Bigram

想象一棵分类树：最顶层把所有视频分成 K 个大类（c₁），每个大类里再分 K 个子类（c₂），子类再分（c₃）...直到每个叶子代表一个具体视频。RQ-VAE 就是用残差量化自动学出这棵树——先量化粗粒度信息得到 c₁ 和残差，再量化残差得到 c₂ 和更精细的残差，如此递推。

深度截断 Bigram 的意思是：在用户序列里只用前两层 (c₁, c₂)。为什么只取两层？因为序列里有 2000 个视频，每个如果都用 8 层编码，码本爆炸（8⁸ 种组合）。只取两层（K² 种组合），embedding 表小而紧凑，同时"子垂类"粒度（如"游戏-沙盒"）已经足够区分用户兴趣模式。候选侧用更多层因为只有一个候选需要匹配，不存在 2000 倍的放大。

**具体例子**：假设码本大小 K=1024。全 Bigram 空间只有 1024×1024 = ~100万种 embedding。相比之下，短视频平台的视频数可能是数亿级——传统方案需要数亿行 embedding 表。Bigram 策略把存储从 O(corpus) 缩到 O(K²)，减少了 38% 的 embedding 参数。

### 概念二：时间折叠（Temporal Folding）vs 池化

时间折叠不是池化。池化（mean/max pooling）是有损的——4 个 embedding 被压成 1 个，信息丢失了。时间折叠是 reshape——4 个 d 维向量被拼成 1 个 4d 维向量，所有信息都保留。这只是换了一种"看"数据的方式：原来是"2000 个低维 token"，现在是"500 个高维 token"。

为什么这不仅仅是省计算？因为拼接后的"超级 token"里，相邻 4 帧的交互信息被内化为特征维度上的相关性——后续 FFN 层可以直接用乘法捕捉这些局部关系，不需要注意力机制显式建模。实验验证 k=4 时 AUC 反而比 vanilla Transformer **提高** 了 0.06%/0.15%（两个任务），说明这种"强制局部交互→FFN 建模"的归纳偏置是正面的。

### 概念三：Global Query Token 作为 Attention Sink

Transformer 里有个奇特现象：如果不给 attention 一个"垃圾桶"，那些无关 token 的注意力得分会被迫分散到所有位置，干扰有意义的交互。StreamingLLM（Xiao et al. 2023）发现 LLM 第一个 token 充当了天然的 attention sink。这篇论文把这个发现工程化——主动放一个可学习的 Global Query Token 在序列头部，让低熵信号（"我不知道关注啥"的 token）有个地方倾倒垃圾，稳定剩余 token 之间的有效交互。

## 博导审稿

**选题眼光**：这个问题值得做，而且卡位非常好——表示瓶颈和计算瓶颈是两个独立的"真缺口"，它们的协同效应更是学术界一直忽视的空白。工业界早就知道这两个问题同时存在，但没有人在十亿用户规模上同时解决它们并给出数据。选题是真实的工业痛点，不是人造缺口。

**方法成熟度**：巧劲为主。时间折叠本质上是一个 reshape 操作——把这个微不足道的操作和 attention sink 机制组合起来，就能在降低 92.2% 内存的同时反而提升 AUC，这种"用结构化归纳偏置代替暴力计算"的设计哲学很优雅。Bigram 策略也是同样的风格——不需要新的训练 trick，只需要一个"取两层就够了"的洞察。整套方案没有引入任何复杂的新模块，这在工业论文中很难得。

**实验诚意**：在线 A/B 实验在十亿用户规模上跑出了统计显著的结果（活跃用户 +0.52%、满足观看时长 +1.42%），这是硬指标。Scaling law 分析（Figure 4）和消融实验（k=4 vs k=6 的对比）也表明作者认真探索了超参空间。但有几个遗憾：（1）没有和 LONGER（字节）、HSTU（Meta）这些同级别的工业竞品做直接对比，只在相关工作里提了一嘴；（2）Figure 3/4 只有离线 AUC，没有给出不同序列长度在线 A/B 的逐级对比；（3）SID 的碰撞问题（同一 Bigram 对应多个视频）没有讨论。

**写作功力**：6 页的会议论文写得紧凑清晰，方法描述几乎没有冗余。Section 2.2 的"非对称粒度策略"用半页讲清楚了一个很有洞察的设计决策。但 Related Work 放在 Section 1 里有些拥挤，把 LONGER/HyFormer/DV365/HSTU/VISTA 全塞进一段，读者很难消化它们的差异。另外，全文没有一张"系统全貌图"——Figure 2 只画了 Transformer 组件，但序列侧和候选侧的非对称粒度、同步/异步模块的关系、SID 生成到推理的全流程都缺少可视化。

**一句话判决**：**Accept**。十亿用户规模的双瓶颈同时解决方案，方法简洁有效，在线结果过硬。缺少直接竞品对比和碰撞讨论是主要扣分项，但不影响其工业贡献的实质价值。

## 启发

这篇论文最打动我的地方有三个：

**第一，"只取两层"的非对称粒度策略。** 对于序列侧 2000 个 token 用粗粒度、候选侧 1 个 token 用细粒度——这个设计背后的直觉是：判断"用户对哪个子垂类感兴趣"只需要大量粗粒度信号的统计涌现，而判断"这个候选是否匹配"需要精细区分。这种"不同位置用不同精度"的思想对我们自己的 SID 方案有直接启发——不是所有地方都需要全深度 SID。

**第二，时间折叠是一个被严重低估的 trick。** 零参数、零信息损失、O(L²/k²) 加速，同时还引入了"相邻 token 强制局部交互"的归纳偏置——在推荐场景里这个偏置是正面的（相邻行为确实高度相关）。这个 trick 可以直接叠加在任何 Transformer-based 的序列模型上，不需要修改训练流程。

**第三，Scaling Law 实证。** Figure 4 展示了推荐系统中"序列长度-训练计算量-性能"也遵循 power-law scaling，指数分别是 -0.634 和 -0.056。这暗示推荐系统的 scaling behavior 和 LLM 是类似的——增加序列长度的边际收益递减但始终为正。对于"是否值得继续推长序列"这个工业决策问题，这是一个重要的定量参考。
