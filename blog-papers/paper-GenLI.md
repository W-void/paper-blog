## 缺口：GSU 的两个原罪

长期用户兴趣建模（Long-term User Interest Modeling）是 CTR 预估里的一个经典难题。用户历史行为序列动辄几千条，全量做 attention 计算量爆炸，所以工业界普遍采用两阶段框架：先用一个轻量的 GSU（General Search Unit）从几千条行为里捞出 top-k 条相关行为，再用重量级的 ESU（Exact Search Unit）做精细 attention 聚合。SIM、ETA、SDIM、TWIN 都是这个框架下的变体。

这套框架有两个根本性的缺陷，而且这两个缺陷是相互关联的：

**第一个缺陷：以目标物品为中心（target-centered）**。GSU 的检索逻辑是"找和当前候选物品最相似的历史行为"。这意味着它只能捞出和候选物品相关的那部分兴趣，用户其他方向的兴趣被系统性地丢弃了。一个用户可能同时喜欢美食、健身、旅游，但如果当前候选是一家餐厅，GSU 只会捞出历史里的美食行为，健身和旅游的兴趣信号完全消失。用户兴趣的多样性被截断了。

**第二个缺陷：逐一比对（pairwise matching）的效率瓶颈**。GSU 的检索方式是把候选物品和每一条历史行为做相似度计算（内积、Hamming 距离、hash 碰撞……），时间复杂度是 O(L·d)，L 是行为序列长度，d 是向量维度。随着平台积累的用户行为越来越长，这个计算量线性增长，成为在线服务的瓶颈。更糟糕的是，pairwise 架构天然忽略了行为之间的交互信息——它只知道"行为 A 和候选物品有多像"，不知道"行为 A 在整个行为序列的上下文里意味着什么"。

这两个缺陷指向同一个根源：GSU 的设计哲学是"检索"，而检索天然是 target-driven 的。要同时解决多样性和效率问题，需要换一个设计哲学。

**这篇论文要填的缝**：能不能不做检索，而是先"生成"用户的兴趣分布，再用 O(1) 的查表操作完成行为筛选，同时捕捉多维度的用户兴趣？

## 增量

**Before**：GSU 以候选物品为锚点，逐一比对历史行为，捞出相关子集；兴趣是单一的、target-driven 的；序列越长，检索越慢。

**After**：IGM 先从短期行为生成三种兴趣分布（显式/隐式/相对），完全不看候选物品；BRM 用 O(1) 查表给每条历史行为打分；兴趣是多维的、target-independent 的；序列越长，效率优势越明显。

**一句话增量**：把 GSU 的"检索"范式替换为"生成+查表"范式，在提升兴趣多样性的同时把单条行为评分复杂度从 O(d) 降到 O(1)。

## 核心机制图

```
输入：用户行为序列 B = [b1, b2, ..., bL]（长期，最长1000条）
         │
         ├── 短期行为 [b1,...,bl]（最近 l 条，如100条）
         │
         ▼
┌──────────────────────────────────────────────────────────┐
│  IGM：兴趣生成模块（target-independent）                   │
│                                                          │
│  Query: [e1（最新行为）; eq（可学习向量）]                  │
│  Key/Value: [e1; e2; ...; el]（短期行为 embedding）        │
│                                                          │
│  MHA → 隐兴趣 embedding h                                 │
│                                                          │
│  h_E → MLP → softmax → p_E（显式兴趣分布，N=4096维）       │
│  h_I → MLP → softmax → p_I（隐式兴趣分布，N=4096维）       │
│  p_R = softmax(p_E - p_I)（相对兴趣分布）                  │
│                                                          │
│  训练信号：                                               │
│    p_E 用点击行为监督（最大化被点击物品的概率）               │
│    p_I 用曝光行为监督（最大化被曝光物品的概率）               │
│    p_R 无额外监督，由 p_E 和 p_I 差值定义                   │
└──────────────────────────────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────────────────────┐
│  BRM：行为检索模块                                         │
│                                                          │
│  对每条历史行为 bi：                                       │
│    score(bi, p) = p[ID(bi) % N]   ← O(1) 查表！           │
│                                                          │
│  分别在 p_I、p_E、p_R 上取 top-k 行为                      │
│  → B_I（k条）、B_E（k条）、B_R（k条），共 K=3k 条           │
└──────────────────────────────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────────────────────┐
│  IFM：兴趣融合模块                                         │
│                                                          │
│  B_I → MHA（query=目标物品 embedding）→ z_I               │
│  B_E → MHA → z_E                                         │
│  B_R → MHA → z_R                                         │
│                                                          │
│  z_F = concat(z_I, z_E, z_R)                             │
│  g = sigmoid(MLP(z_F))                                   │
│  x_l = (g ⊗ z_F) · W_g   ← 门控输出长期兴趣特征            │
└──────────────────────────────────────────────────────────┘
         │
         ▼
   x = concat(x_l, x_s, x_o, e_t) → MLP → CTR 预测
```

## 白话方法：图书馆的"预判式"选书

传统 GSU 的逻辑是：你来借书，馆员拿着你要借的那本书（候选物品），在书库里逐一比对，找出和它最像的书（相关历史行为）。这个过程有两个问题：第一，只找和这本书像的，你其他方向的阅读兴趣被忽视了；第二，书库越大，比对越慢。

GenLI 的逻辑是：馆员不等你来，提前根据你最近借的几本书（短期行为），预判你现在可能感兴趣的方向，生成一张"兴趣地图"（兴趣分布）。这张地图有三层：

第一层是**显式兴趣地图**（p_E）：根据你最近点击了什么，预测你接下来最可能点击哪类书。训练时用真实点击行为来校准这张地图。

第二层是**隐式兴趣地图**（p_I）：根据平台给你曝光了什么（不管你点没点），预测你的潜在偏好。曝光行为是平台对你兴趣的粗略推断，比点击更稳定、更长期。

第三层是**相对兴趣地图**（p_R = p_E - p_I）：显式兴趣减去隐式兴趣，得到的是"你在被曝光的内容里，更倾向于点哪类"。这张地图捕捉的是你的决策偏好——不是绝对喜欢什么，而是在给定选项里相对更喜欢什么。

有了这三张地图，馆员给书库里每本书打分就变成了查地图：直接查这本书的 ID 对应地图上哪个格子，O(1) 完成。不需要再拿候选书逐一比对了。

最后，从三张地图各选出 top-k 本书，分别做 attention 聚合，再门控融合，得到长期兴趣特征。

## 关键概念费曼讲解

### 概念一：target-independent 兴趣生成

**从零建起**：传统 GSU 的问题在于，它的输出完全由候选物品决定——换一个候选物品，检索结果就完全不同。这意味着每次推理都要重新做一遍检索，而且检索结果只反映了和当前候选相关的那部分兴趣。

GenLI 的 IGM 完全不看候选物品。它只看用户最近的短期行为，生成一个"当前用户兴趣的全景快照"——一个 N 维的概率分布，每个维度对应一类物品（通过 ID 取模映射）。这个分布一旦生成，就可以对任意候选物品做 O(1) 查表，不需要重新计算。

**用例子落地**：用户最近看了 10 个视频：3 个美食、4 个健身、3 个旅游。IGM 生成的显式兴趣分布 p_E 在美食、健身、旅游对应的维度上都有较高概率。当候选物品是一家餐厅时，查表得到它在 p_E 上的分数；当候选物品是一个健身器材时，同样查表。两次查表用的是同一张分布，不需要重新计算。

### 概念二：相对兴趣分布 p_R = softmax(p_E - p_I)

**从零建起**：这是全文最有意思的设计。p_E 是点击分布，p_I 是曝光分布。两者的差值代表什么？

曝光是平台的选择，点击是用户的选择。如果某类内容被大量曝光但点击率低，说明用户对它的兴趣低于平台预期；如果某类内容曝光不多但点击率高，说明用户对它的兴趣超出平台预期。p_E - p_I 捕捉的正是这种"超出预期的偏好"——用户在给定曝光池里的相对决策倾向。

**用例子落地**：平台给用户曝光了 100 个物品，其中 60 个美食、30 个健身、10 个旅游。用户点击了 20 个美食、15 个健身、8 个旅游。点击率分别是 33%、50%、80%。p_I 在美食维度高（曝光多），p_E 在旅游维度高（点击率高）。p_R = p_E - p_I 在旅游维度最高，说明用户对旅游内容的兴趣被平台严重低估了。这个信号对推荐系统非常有价值。

### 概念三：O(1) 查表检索

**从零建起**：传统 GSU 给每条历史行为打分的方式是：把行为 embedding 和候选物品 embedding 做内积，复杂度 O(d)，d 是向量维度。序列有 L 条行为，总复杂度 O(L·d)。

GenLI 的 BRM 打分方式是：`score(bi, p) = p[ID(bi) % N]`。把行为的 ID 对 N 取模，得到一个索引，直接查分布 p 的对应位置，复杂度 O(1)。序列有 L 条行为，总复杂度 O(L)。

**用例子落地**：N=4096，行为 bi 的 ID 是 12345。12345 % 4096 = 57。直接查 p[57]，得到这条行为在当前兴趣分布下的重要性分数。整个过程就是一次数组索引，没有任何向量运算。

这个设计的代价是：不同 ID 的行为可能映射到同一个索引（hash 碰撞），导致分数不精确。N 越大，碰撞概率越低，但内存占用越大。实验显示 N=4096 是一个合适的平衡点。

## 餐巾纸速写：从"检索"到"生成+查表"

```
旧范式（target-centered retrieval）：
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  候选物品 ──────────────────────────────────────────┐   │
│                                                     │   │
│  历史行为 b1 ──── sim(b1, target) ──────────────────┤   │
│  历史行为 b2 ──── sim(b2, target) ──────────────────┤   │
│  ...                                                │   │
│  历史行为 bL ──── sim(bL, target) ──────────────────┤   │
│                                                     ▼   │
│                                              top-k 行为  │
│                                                         │
│  问题：O(L·d) 复杂度；只捕捉 target 相关兴趣；忽略行为交互  │
└─────────────────────────────────────────────────────────┘

新范式（target-independent generation + lookup）：
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  短期行为 [b1,...,bl]                                    │
│       ↓ MHA（含可学习 query，捕捉行为交互）                │
│       ↓ MLP + softmax                                   │
│  p_E（显式）、p_I（隐式）、p_R（相对）← 三张兴趣地图        │
│                                                         │
│  历史行为 bi → ID(bi)%N → 查表 → score  ← O(1) per行为   │
│                                                         │
│  候选物品只在 IFM 阶段出现（作为 attention query）         │
│                                                         │
│  核心位移：兴趣建模从"以候选为中心"变为"以用户为中心"        │
└─────────────────────────────────────────────────────────┘
```

**一句话核心位移**：以前是"拿着候选物品去历史里找相关行为"，现在是"先把用户当前兴趣全景生成出来，再用查表决定哪些历史行为重要"。

## 博导审稿

**选题眼光**：问题是真实的，target-centered GSU 的局限性在工业界确实存在，而且随着行为序列越来越长，效率问题会越来越突出。把"生成"引入长期兴趣建模这个角度是新的，但"生成"这个词用得有点虚——IGM 本质上是一个 MHA+MLP 的分类器，输出一个 softmax 分布，和 NLP 里的生成模型（自回归、扩散等）没有太大关系。用"生成"来包装有蹭热点之嫌，但核心思路（target-independent 兴趣分布 + O(1) 查表）是有实质价值的。

**方法成熟度**：三个模块的技术都是成熟的。真正的创新点集中在两处：一是 target-independent 的兴趣分布生成（用短期行为生成全局兴趣快照，而非 per-candidate 检索）；二是 O(1) 查表替代 O(d) 内积（本质是一个 hash-based 近似，用 ID 取模映射到分布索引）。相对兴趣分布 p_R = softmax(p_E - p_I) 是全文最有创意的设计，把点击/曝光的差值解释为用户的相对决策偏好，这个视角是新颖的。

**实验诚意**：数据集选取合理（Amazon Book、TaoBao、美团工业数据集），baseline 覆盖了 SIM、ETA、SDIM、TWIN 等主流方法。工业数据集规模真实（1.1B 样本）。在线 A/B 测试在美团外卖平台跑了 6 天，30% 流量，RPM +1.567%，这个数字在广告系统里是相当显著的。

有几个地方值得追问：第一，O(1) 查表的代价是 hash 碰撞，但论文没有分析碰撞率对性能的影响（只做了 N 的敏感性分析，没有直接报告碰撞率）。第二，p_R 的设计动机讲得很清楚，但消融实验显示去掉 p_R 只掉了 0.42%（Amazon）和 0.27%（TaoBao），是三个分布里贡献最小的，和论文对它的重视程度不太匹配。第三，论文声称"首次将生成方法引入 CTR 长期兴趣建模"，但 IGM 的 MHA+MLP 架构和 TWIN 的 GSU 差异并不像论文描述的那么大，"生成"的定义边界模糊。

**写作功力**：结构清晰，公式推导完整。Figure 2（推理时间对比）是全文最有说服力的图，直观展示了随序列长度增加 GenLI 的效率优势越来越明显。但论文的 venue 信息是占位符（"Conference acronym 'XX, Woodstock, NY"），说明这是一篇还未正式发表的预印本，审稿意见可能还会要求补充实验。

**一句话判决**：**Weak Accept，偏向 Accept**。核心思路（target-independent 兴趣分布 + O(1) 查表）有实质价值，在线效果真实，工程落地完整。"生成"的包装略显夸张，但不影响方法本身的贡献。如果能补充 hash 碰撞分析和更清晰的"生成"定义，可以升到 Accept。

## 启发

**最值得借鉴的设计：target-independent 兴趣快照**。把用户兴趣建模从"per-candidate 检索"解耦为"全局快照生成"，这个思路在任何需要处理长序列的推荐/广告场景都适用。一旦生成了兴趣分布，对任意候选物品的评分都是 O(1)，这在候选集很大的场景（比如广告召回）里有很强的工程价值。

**相对兴趣分布 p_R 的视角值得深挖**。用点击分布减曝光分布来捕捉"超出平台预期的偏好"，这个思路可以推广：在任何有"系统推荐"和"用户选择"两个信号的场景里，两者的差值都可能包含有价值的信息。比如搜索场景里，"点击分布 - 展示分布"可以捕捉用户对搜索结果排序的隐式反馈。

**一个被照亮的盲区**：现有长期兴趣建模的大多数工作都在优化"如何更准确地检索相关行为"，但 GenLI 提醒我们，检索的准确性不是唯一目标——兴趣的多样性和覆盖度同样重要。当 K 很小时（检索行为数量有限），GenLI 的优势最明显，正是因为它能在有限的 K 个槽位里覆盖更多维度的兴趣，而不是把所有槽位都给了和候选最相似的行为。
