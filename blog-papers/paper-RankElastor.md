## 缺口：推荐模型扩容时，表示空间在悄悄坍塌

推荐系统的规模化是近年来的核心命题。大家都在往更深、更宽的方向堆模型，期待像 LLM 那样享受 scaling law 的红利。RankMixer 是这个方向上最受关注的架构之一——它把多字段 embedding 统一成 token 矩阵，交替执行 token mixing 和 per-token FFN（P-FFN），在多个 benchmark 上取得了 SOTA 表现，也在工业系统里成功落地。

但有一个问题没人认真看过：**RankMixer 的表示空间到底有没有被充分利用？**

这个问题的背后是"embedding collapse"——一个在推荐系统 scaling 研究中越来越被重视的现象。简单说，就是模型学出来的表示矩阵退化成了低秩的，大量奇异值趋近于零，表示多样性严重不足。你花了很多参数扩大了表示空间，但实际上只用了其中一个角落。这个问题在 DCNv2、xDeepFM 这类传统推荐模型里已经有人研究过，但 RankMixer 这种 token-transformation 架构的情况，完全是空白。

本文填的就是这条缝：**系统性分析 RankMixer 的 embedding collapse 行为，找到根因，然后提出修复方案。**

## 增量：从"阻尼振荡"到"扩得更多、缩得更少"

这篇论文让我们知道了一件以前不知道的事：**RankMixer 的有效秩（effective rank）在层间呈现"阻尼振荡"轨迹——token mixing 小幅扩张，P-FFN 大幅收缩，净效果是 collapse 没有被根本解决。** 而 RankElastor 通过参数化全混合（Parameterized Full Mixing）和 GLU 改进的 P-FFN，把这个轨迹改造成"扩得更多、缩得更少"，在 Criteo 和 Avazu 上 AUC 超过最强 baseline 超过 0.001，同时展现出更好的 scaling 行为。

## 关键概念：有效秩是什么，为什么它比"秩"更有用

在深入方法之前，需要先把"有效秩"这个概念讲清楚。

代数秩（algebraic rank）是矩阵中线性无关行/列的数量，是一个整数。但它有个问题：一个矩阵可能有 100 个非零奇异值，但其中 99 个都是 0.0001，只有 1 个是 100。代数秩说这个矩阵是满秩的，但实际上它的信息几乎全集中在一个方向上，其他方向形同虚设。

有效秩（effective rank）解决了这个问题。本文采用的定义是"稳定秩"（stable rank）：

```
erank(X) = ||X||²_F / ||X||²_2 = Σσᵢ² / max(σᵢ²)
```

直觉上，这是"所有奇异值的平方和"除以"最大奇异值的平方"。如果奇异值分布均匀，这个值接近矩阵的维度；如果奇异值高度集中在少数几个方向，这个值就很小。

用一个具体例子来感受：假设你有一个 20×20 的表示矩阵，代数秩是 20（满秩），但奇异值是 [100, 1, 1, 1, ..., 1]（1 个大的，19 个小的）。有效秩大约是 (100² + 19×1²) / 100² ≈ 1.0019，几乎等于 1。这意味着这个矩阵虽然"满秩"，但实际上只在一个方向上有信息，其他 19 个维度几乎没有被利用。

在推荐系统里，有效秩低意味着：你花了大量参数学习 embedding，但所有用户/物品的表示都挤在一个低维子空间里，模型的表达能力被严重浪费。

## 核心机制：RankMixer 的阻尼振荡，以及 RankElastor 的两把手术刀

### RankMixer 的病理分析

RankMixer 的 token mixing 本质上是一个**块转置操作**：把 token 矩阵 X ∈ ℝ^{T×D} 按 T×T 的块网格分割，然后把块 X_{ij} 和 X_{ji} 互换，再与原矩阵做残差相加。

用数学语言写出来是：

```
vec(M⊤) = LN(P ⊗ I) vec(X⊤) + vec(X⊤)
```

其中 P 是一个置换矩阵（commutation matrix），I 是单位矩阵，⊗ 是 Kronecker 积。

这个操作的问题在于：P 是固定的置换，不是可学习的。Theorem 2.1 证明了，块转置混合确实能提升有效秩（下界是 2kμ/(√k+√μ)²），但这个提升是有上界的（上界是 2(k+μ)）。更关键的是，当 embedding 在初始化阶段就已经低秩时，这个有界扩张往往只能带来很小的改善。

P-FFN 的问题更严重。Theorem 2.2 证明了：当输入表示已经低秩时，标准的 GELU-based FFN 会进一步**收缩**有效秩——要么确定性地（rank-1 输入），要么以高概率（一般低秩输入）。这就是为什么每次经过 P-FFN 之后，有效秩都会下降。

两个模块合在一起，就产生了论文观察到的"阻尼振荡"：token mixing 小幅扩张 → P-FFN 大幅收缩 → token mixing 再小幅扩张 → P-FFN 再大幅收缩……最终有效秩在一个较低的水平上震荡，没有根本性的提升。

### RankElastor 的两把手术刀

**第一把：参数化全混合（Parameterized Full Mixing）**

把固定置换矩阵 P 换成可学习的混合矩阵 W ∈ ℝ^{TD×TD}：

```
vec(M⊤) = LN(W + I) vec(X⊤)
```

这相当于把块粒度从 d = D/T 降到 d* = 1（最细粒度），同时把置换操作换成全参数化的线性变换。Theorem 3.1 证明了，任何 d* > 1 的块混合方案都是 d* = 1 的严格子集——也就是说，参数化全混合的表达能力严格强于原始的块转置混合。

代价是计算复杂度从 O(TD) 升到 O(T²D²)，参数量也从 0 升到 O(T²D²)。但在实际配置下（T=15, D=26），这个开销是可接受的，实验显示训练时间只增加了 10%~15%。

**第二把：GLU 改进的 P-FFN**

把 GELU-based FFN 换成 GLU-style 的门控前馈网络：

```
Z_t = GELU(M_t W₁) ⊙ (M_t W₂) W₃ + M_t W_r
```

其中 ⊙ 是 Hadamard 积（逐元素乘法），W₁, W₂ 是升维投影，W₃ 是降维投影，W_r 是可学习的残差映射。

GLU 的核心是**乘法交互**：GELU(M_t W₁) 是一个非线性门，(M_t W₂) 是线性通路，两者相乘产生二阶特征交互。Theorem 3.2 证明了，这种乘法结构能把有效秩从 k 提升到 k+δ（δ > 0），而不是像标准 FFN 那样收缩到 αk（α < 1）。

直觉上：标准 FFN 是"先升维再降维"，信息在降维时不可避免地被压缩；GLU 的乘法门控相当于在升维空间里做了一次"特征选择"，保留了更多有用的方向，降维时损失更小。

### 架构对比速写

```
RankMixer 的每个 Block：
┌─────────────────────────────────────────────────────┐
│  X ──→ [块转置置换 P⊗I，固定，无参数] ──→ 残差+LN  │
│  M ──→ [GELU-FFN，可能收缩有效秩]      ──→ 残差+LN  │
└─────────────────────────────────────────────────────┘
         ↑ token mixing 小幅扩张，P-FFN 大幅收缩

RankElastor 的每个 Block：
┌─────────────────────────────────────────────────────┐
│  X ──→ [全参数化混合矩阵 W，可学习]    ──→ 残差+LN  │
│  M ──→ [GLU-FFN，乘法门控，提升有效秩] ──→ 残差+LN  │
└─────────────────────────────────────────────────────┘
         ↑ token mixing 大幅扩张，P-FFN 温和收缩
```

## 白话类比：从"固定路线公交"到"自由换乘地铁"

把 token 矩阵想象成一座城市里的 T 个区域，每个区域有 D 条街道（特征维度）。

RankMixer 的 token mixing 是一辆**固定路线的公交车**：每次都按照预设的路线（块转置置换）在区域之间交换信息，路线是死的，不管当前哪些区域之间的信息交换更有价值。P-FFN 是每个区域内部的**单向高速公路**：信息进去之后，出来的时候维度被压缩了，一些街道被关闭了。

RankElastor 的 Parameterized Full Mixing 是**自由换乘的地铁网络**：每个区域的每条街道都可以和其他任何区域的任何街道直接连通，连通的权重是可学习的，模型自己决定哪些连接最有价值。GLU-improved P-FFN 是**带智能分流的双向道路**：乘法门控相当于一个智能交通系统，根据当前流量（特征值）动态决定哪些方向保持畅通，避免了单向高速公路的信息损失。

这个类比的承重点：公交路线固定 ↔ 置换矩阵固定；地铁自由换乘 ↔ 全参数化混合矩阵；单向高速公路压缩 ↔ FFN 有效秩收缩；智能分流双向道路 ↔ GLU 乘法门控保持有效秩。

## 实验结果：数字说话

**CTR 预测性能（Table 2）**

在 Criteo 和 Avazu 两个工业级 benchmark 上，RankElastor 超过所有 baseline，包括 RankMixer：

| 模型 | Criteo AUC | Avazu AUC |
|------|-----------|-----------|
| MLP | 0.81307 | 0.79226 |
| DCNv2 | 0.81365 | 0.79258 |
| RankMixer | 0.81375 | 0.79270 |
| **RankElastor** | **0.81482** | **0.79323** |

AUC 提升超过 0.001，在工业级 CTR benchmark 上被认为是统计显著的改进（参考 DIN 论文的标准）。

**有效秩动态（Figure 5 vs Figure 1）**

RankElastor 的有效秩分布在每个模块后都有更大的右移（扩张更多），而 P-FFN 后的左移（收缩）明显更小。在 Avazu 上，RankMixer 的有效秩在 P-FFN 后会出现明显的 collapse 趋势，而 RankElastor 全程保持稳定增长。

**Scaling 行为（Figure 7, 8）**

在宽度、深度、联合 scaling 三种方案下，RankElastor 的 AUC 随参数量增加的提升幅度都显著大于 RankMixer。这是最重要的结果之一：它说明 RankElastor 不只是在当前规模下更好，而是在更大规模下优势会进一步扩大。

**消融实验（Table 3）**

去掉 Full Mixing（退化为块转置）：AUC 下降 0.00069（Criteo）。换回 GELU-based FFN：AUC 下降 0.00133（Criteo）。两个模块有协同效应：单独加 GLU 到 RankMixer 只有微小提升，但在 Full Mixing 的基础上加 GLU 效果显著——说明 GLU 的有效秩保持能力需要 Full Mixing 先把有效秩扩张到足够高的水平才能充分发挥。

**行为序列建模泛化（Table 4）**

在 KuaiVideo 和 TaobaoAd 两个行为序列建模任务上，RankElastor 同样超过所有 baseline，说明方法不局限于标准 CTR 预测场景。

## 博导审稿：带了二十年研究生的老教授怎么看

**选题眼光**：这个问题值得做。RankMixer 是近两年推荐 scaling 方向最受关注的架构，但它的 collapse 行为确实没人系统研究过。从"有效秩动态"这个角度切入，既有理论深度，又有实践价值，选题眼光不错。

**方法成熟度**：两个模块的设计都有理论支撑，四个定理（2.1、2.2、3.1、3.2）构成了完整的理论链条：先证明原始模块为什么不够好，再证明新模块为什么更好。这种"诊断→修复→证明"的结构是扎实的。GLU 的选择也不是拍脑袋——它在 LLM 领域（LLaMA、PaLM 等）已经被广泛验证，把它引入推荐系统的 P-FFN 是合理的迁移。

**实验诚意**：Baseline 选择公道，包括了 RankMixer 本身和几个代表性的特征交互模型。10 次随机初始化取平均，统计可靠性有保证。消融实验设计合理，揭示了两个模块的协同效应。Scaling 实验是亮点，直接回答了"这个架构能不能 scale"的问题。

**写作功力**：论文结构清晰，"诊断→理论→方法→实验"的叙事逻辑流畅。Figure 1 和 Figure 5 的对比设计很聪明，直观展示了 RankMixer 和 RankElastor 的有效秩动态差异。有一处偷懒：复杂度分析（Section 3.3）只给了 O 符号，没有给出具体的参数量数字，读者需要自己代入 T、D 的值才能感受到实际开销。

**潜在质疑**：参数化全混合的 O(T²D²) 复杂度在 T 和 D 较大时会成为瓶颈。论文的实验配置是 (T=15, D=26) 或 (T=16, D=24)，这是相对小的配置。如果 T=64, D=128（更大规模的工业系统），参数量会爆炸。论文没有讨论这个 scalability 限制，是一个明显的缺口。

**一句话判决**：**Weak Accept 偏 Accept**。理论扎实，实验充分，工程价值清晰。主要局限是参数化全混合在大规模配置下的可行性没有讨论，以及实验数据集（Criteo/Avazu）是公开 benchmark，缺少更大规模工业数据集的验证。

## 启发：这篇论文照亮了哪些盲区

**第一个盲区：有效秩是推荐模型设计的一个被忽视的指标。** 我们通常用 AUC、LogLoss 来评估推荐模型，但这些指标是结果，有效秩是过程。一个有效秩持续下降的模型，即使当前 AUC 还不错，在 scaling 时也会遇到瓶颈。把有效秩动态作为架构设计的约束条件，是一个值得推广的思路。

**第二个盲区：GLU 在推荐系统 FFN 中的潜力。** GLU 在 LLM 领域已经是标配（LLaMA 用的就是 SwiGLU），但在推荐系统的特征交互模块里几乎没有人用。这篇论文给出了理论解释（乘法交互提升有效秩）和实验验证，是一个可以直接借鉴的改进点。

**第三个盲区：token mixing 的参数化程度和表达能力的关系。** RankMixer 的块转置是一个极端（完全无参数），全参数化混合矩阵是另一个极端（O(T²D²) 参数）。中间有没有更好的权衡点？比如低秩参数化的混合矩阵（W = UV⊤，U, V ∈ ℝ^{TD×r}），可以在保持较高表达能力的同时控制参数量。这是一个值得探索的方向。

**对工业实践的直接启示**：如果你的推荐系统正在使用 RankMixer 或类似的 token-transformation 架构，可以考虑：（1）监控每层的有效秩，如果发现 P-FFN 后有效秩大幅下降，这是一个需要关注的信号；（2）把 GELU-based FFN 换成 GLU-style FFN 是一个低成本的改进，参数量只增加约 3 倍（r=3 的配置），但有效秩保持能力显著提升；（3）参数化全混合在小 T、小 D 的配置下是可行的，但在大规模配置下需要考虑低秩近似。
