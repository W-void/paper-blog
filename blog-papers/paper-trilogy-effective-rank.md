## 一、故事的起点：一个被忽视的问题

推荐系统的 scaling 研究在 2024–2026 年间进入了一个新阶段。Wukong、RankMixer、TokenMixer-Large 等工作相继证明，MetaFormer 架构在推荐系统里同样存在 scaling law——堆更多参数、更深的层、更长的行为序列，AUC 就会持续提升。这个结论令人振奋，工业界纷纷跟进。

但腾讯的这个团队在做 RankMixer 的时候，注意到了一件奇怪的事：**模型越深，表示空间的利用率反而越低。**

他们用"有效秩"（effective rank）来量化这个现象。有效秩不是代数意义上的矩阵秩，而是对奇异值分布均匀程度的度量——如果所有奇异值都差不多大，有效秩接近矩阵维度；如果奇异值高度集中在少数几个方向，有效秩就很小。一个有效秩低的表示矩阵，意味着模型虽然有很多参数，但实际上只在一个低维子空间里工作，大量的表示容量被浪费了。

他们发现，RankMixer 的有效秩在层间呈现"阻尼振荡"：token mixing 之后小幅上升，P-FFN 之后大幅下降，净效果是有效秩在一个较低的水平上震荡，随着深度增加甚至还会进一步退化。这意味着，scaling 带来的参数增长，并没有转化为等比例的表示容量增长。

这个发现是三篇论文共同的起点。三篇论文从三个不同的角度，对这个问题给出了各自的回答。

## 二、三条路径，同一个问题

### 路径一：修复架构内部的"阻尼振荡"（RankElastor）

RankElastor 的切入点是最直接的：**既然 RankMixer 的两个模块（token mixing 和 P-FFN）都有问题，那就把两个模块都修掉。**

Token mixing 的问题在于，它用的是固定的块转置置换（commutation matrix），这是一个无参数的操作。理论上可以证明，这种固定置换对有效秩的提升是有上界的，而且当初始表示已经低秩时，这个提升往往很小。RankElastor 把它换成了可学习的全参数化混合矩阵，让模型自己决定哪些 token 之间的信息交换最有价值。

P-FFN 的问题在于，标准的 GELU-based FFN 在低秩输入下会进一步收缩有效秩——先升维再降维，降维时不可避免地丢失信息。RankElastor 把它换成了 GLU-style 的门控前馈网络，用乘法交互（GELU 门 × 线性通路）代替纯线性变换，理论上可以证明这种乘法结构能把有效秩从 k 提升到 k+δ，而不是收缩到 αk。

两个修改合在一起，把"阻尼振荡"改造成了"扩得更多、缩得更少"的轨迹。在 Criteo 和 Avazu 上，AUC 超过 RankMixer 超过 0.001，而且在 scaling 实验中，优势随参数量增加而扩大。

这条路径的本质是：**在 token-transformation 架构内部，通过提升两个核心模块的表达能力来对抗 collapse。**

### 路径二：从输入端扩充表示多样性（RankUp）

RankUp 的切入点不同。它认为，仅仅改进 token mixing 和 FFN 的设计，是在一个已经受限的表示空间里做文章，治标不治本。**真正的问题在于，输入端的表示多样性就已经不够了。**

RankUp 提出了五个机制，从不同角度扩充输入端的表示多样性：

第一，随机置换分割（Randomized Permutation Splitting）。传统的 token 分组方式（语义分组或等距分割）会把高度相关的特征聚在同一个 token 里，导致 token 之间的互信息很高，有效秩低。随机置换打破了这种相关性，让每个 token 都包含来自不同语义域的特征，从而提升 token 之间的统计独立性。

第二，多 embedding 范式（Multi-embedding Paradigm）。传统系统用单一 embedding 表把稀疏特征映射到潜在空间，这是一个固定的低维约束。多 embedding 用多个独立的 embedding 表，让同一个特征从多个几何视角被表示，提升初始表示矩阵的有效秩。

第三，全局 token（Global Token Integration）。在 MetaFormer 架构里，每个 token 只编码一个局部特征子集的信息。全局 token 聚合所有特征的信息，为后续的 token mixing 提供全局上下文，防止深层的有效秩退化。

第四，预训练 embedding 交叉集成（Cross Integration of Pre-trained Embeddings）。把来自检索模型的预训练 embedding 通过元素积的方式注入到 token 序列，引入外部语义先验，丰富初始表示空间。

第五，任务特定 token 解耦（Task-Specific Token Decoupling）。在多任务学习场景下，不同任务的梯度会相互干扰，压缩共享表示空间。为每个任务引入独立的 task token，让任务特定信息在 token 层面就被分离，减少梯度干扰。

这五个机制在微信视频号、公众号、朋友圈三个广告场景全量上线，GMV 分别提升 3.41%、4.81%、2.12%。

这条路径的本质是：**不改变 token-transformation 架构本身，而是从输入端和表示初始化的角度，给模型提供更丰富的原材料。**

### 路径三：解决统一建模引入的新型 collapse（TokenFormer）

TokenFormer 面对的是一个不同的问题。它的目标是把多字段特征交互和序列行为建模统一到一个架构里——这是推荐系统领域的一个长期追求，因为工业系统里两者都需要，分开建模会带来大量的工程复杂度和参数冗余。

但统一建模带来了一个新的 collapse 问题，TokenFormer 把它命名为"序列坍塌传播"（Sequential Collapse Propagation，SCP）。问题的根源在于：非序列特征（用户画像、上下文特征等）往往是低基数的，它们的 embedding 天然就是低秩的。当这些低秩的静态特征 token 和高维的序列行为 token 在同一个 Transformer backbone 里交互时，低秩的静态特征会"污染"序列特征的表示，把序列特征的有效秩也拉低。

TokenFormer 用两个机制来对抗 SCP：

第一，底层全注意力-顶层滑动窗口（Bottom-Full-Top-Sliding，BFTS）。浅层用全因果注意力，让静态特征和序列特征充分交互，建立全局上下文；深层切换到收缩窗口的滑动窗口注意力，并且完全丢弃对静态特征位置的注意力。这样，静态特征的低秩噪声只在浅层影响序列特征，深层的序列特征可以专注于局部时序精炼，不再受静态特征的干扰。

第二，非线性交互表示（Non-Linear Interaction Representation，NLIR）。在注意力输出上施加一个 sigmoid 门控的乘法调制：先从层输入计算一个门投影，再用 sigmoid 激活后与注意力输出做逐元素乘法。这种乘法非线性引入了高阶特征交互，理论上可以证明它能保持表示的秩丰富性，防止序列特征在与静态特征交互时被压缩到低维子空间。

在腾讯广告的在线 A/B 测试中，TokenFormer 相比生产基线实现了 4.03% 的 GMV 提升，同时 serving 吞吐量从 126 QPS 提升到 695 QPS（5.5 倍加速，来自 BFTS 的稀疏化和解耦 serving 策略）。

这条路径的本质是：**在统一建模的新场景下，识别出一种新型的 collapse 机制（SCP），并用结构化的注意力层次和非线性门控来对抗它。**

## 三、三篇论文的内在联系

### 共同的理论基础

三篇论文都建立在同一个理论基础上：**有效秩是衡量推荐模型表示质量的核心指标，而不是 AUC 或 LogLoss 这些结果指标。** 有效秩低意味着模型的表示容量没有被充分利用，即使当前 AUC 还不错，在 scaling 时也会遇到瓶颈。

三篇论文都引用了同一个关于有效秩的基础定义（Roy & Vetterli, 2007），但在具体计算上有细微差异：RankElastor 用的是"稳定秩"（stable rank，Frobenius 范数平方除以谱范数平方），RankUp 和 TokenFormer 用的是"指数熵秩"（exp of Shannon entropy of normalized singular values）。两种定义都是对奇异值分布均匀程度的度量，方向一致，但数值范围不同。

### 互补的问题视角

三篇论文解决的是同一个大问题（推荐模型的表示 collapse）的不同子问题：

RankElastor 关注的是 **token-transformation 架构内部的 collapse 机制**——token mixing 和 P-FFN 各自的有效秩动态，以及如何通过改进这两个模块来修复"阻尼振荡"。

RankUp 关注的是 **输入端的表示多样性不足**——稀疏特征的 token 分组方式、embedding 初始化、全局上下文缺失等问题，以及如何从源头上提供更丰富的表示原材料。

TokenFormer 关注的是 **统一建模引入的新型 collapse**——低秩静态特征对高维序列特征的"污染"，以及如何通过结构化的注意力层次和非线性门控来隔离这种污染。

三个视角是互补的，而不是竞争的。一个完整的推荐系统可以同时采用这三篇论文的思路：用 RankUp 的方法提升输入端的表示多样性，用 RankElastor 的方法改进 token-transformation 模块，用 TokenFormer 的方法在统一建模时防止 SCP。

### 共同的设计直觉：乘法非线性是关键

三篇论文在方法上有一个共同的直觉：**乘法非线性（multiplicative nonlinearity）是对抗 collapse 的有效工具。**

RankElastor 的 GLU-improved P-FFN 用 GELU 门 × 线性通路的乘法交互来防止有效秩收缩。TokenFormer 的 NLIR 用 sigmoid 门 × 注意力输出的乘法调制来保持序列特征的秩丰富性。RankUp 的 SwiGLU FFN 同样采用了门控乘法结构。

这个共同直觉有理论支撑：纯线性变换（矩阵乘法）在低秩输入下只能做秩保持或秩收缩，无法做秩扩张；而乘法非线性（两个线性变换的逐元素乘积）可以产生二阶特征交互，从而在理论上实现秩扩张。这个洞察来自 LLM 领域（LLaMA、PaLM 等都用 SwiGLU），三篇论文把它系统地引入了推荐系统的特征交互模块。

### 时间线与引用关系

从 arXiv 时间戳来看，RankElastor（2605.23191，2026年5月）是最晚的，它在参考文献里明确引用了 RankUp（[19]，"Expand More, Shrink Less"，Under Review）。RankUp（2604.17878，2026年4月）在参考文献里引用了 RankElastor 的前身工作（[19]，同一引用）。TokenFormer（2604.13737，2026年4月）与 RankUp 几乎同期发布，两者都引用了 RankMixer 作为基础架构。

这说明三篇论文是同一个团队在同一时期的并行工作，而不是线性的"前作→后作"关系。RankElastor 是对 RankUp 工作的进一步深化（从输入端扩充多样性 → 从架构内部修复 collapse 机制），TokenFormer 则是把这个问题扩展到了统一建模的新场景。

## 四、一个统一的叙事框架

如果用一句话来概括这三篇论文的共同主张，那就是：

**推荐模型的 scaling 不应该只关注参数量的增长，更应该关注表示空间的有效利用率。有效秩是衡量这个利用率的核心指标，而 collapse 是阻碍利用率提升的核心障碍。**

这个主张对应了三个层次的行动：

第一层（RankUp）：**从源头上提供更丰富的表示原材料。** 随机置换打破 token 相关性，多 embedding 扩充初始多样性，全局 token 提供全局上下文，预训练 embedding 注入外部先验，任务 token 解耦多任务干扰。

第二层（RankElastor）：**在架构内部主动对抗 collapse。** 参数化全混合扩大 token mixing 的有效秩提升能力，GLU 门控抑制 P-FFN 的有效秩收缩，把"阻尼振荡"改造成"扩得更多、缩得更少"。

第三层（TokenFormer）：**在统一建模的新场景下识别并对抗新型 collapse。** BFTS 通过结构化的注意力层次隔离低秩静态特征的污染，NLIR 通过乘法非线性保持序列特征的秩丰富性，同时实现了多字段特征交互和序列建模的真正统一。

三个层次叠加，构成了一个完整的"反 collapse"工程体系。

## 五、对工业实践的启示

**启示一：把有效秩监控纳入模型开发流程。** 三篇论文都把有效秩作为核心的中间指标，而不只是看最终的 AUC。在工业系统里，可以在每次模型迭代时监控各层的有效秩动态，如果发现 P-FFN 后有效秩大幅下降，或者深层的有效秩持续退化，这是一个需要关注的信号。

**启示二：GLU/SwiGLU 是推荐系统 FFN 的低成本升级。** 三篇论文都用了某种形式的门控乘法 FFN（GLU、SwiGLU），这在 LLM 领域已经是标配，但在推荐系统里还没有被广泛采用。参数量只增加约 1.5 倍（相比标准 FFN），但有效秩保持能力显著提升。

**启示三：token 分组方式对表示质量有显著影响。** RankUp 的随机置换分割实验表明，语义分组会导致高度相关的特征聚在同一个 token 里，产生低秩的 token 表示。在设计 token 分组策略时，应该考虑 token 之间的统计独立性，而不只是语义相关性。

**启示四：统一建模需要特别关注 SCP。** TokenFormer 的发现提醒我们，把多字段特征和序列特征放在同一个 backbone 里，并不是"免费的午餐"——低秩的静态特征会污染序列特征的表示。在设计统一架构时，需要有意识地隔离这种污染，BFTS 和 NLIR 是两种有效的方法。

**启示五：scaling 的正确姿势是"表示容量 scaling"，而不只是"参数量 scaling"。** 三篇论文共同指出，参数量增长不等于表示容量增长。在做模型 scaling 时，应该同时监控有效秩的变化，确保新增的参数确实在扩充表示空间，而不是在一个已经 collapse 的低维子空间里做无效的参数堆叠。

## 六、开放问题

这三篇论文留下了一些值得继续探索的问题。

RankElastor 的参数化全混合在 T 和 D 较大时会遇到 O(T²D²) 的复杂度瓶颈。低秩参数化的混合矩阵（W = UV⊤）是一个自然的解决方向，但如何在保持表达能力的同时控制参数量，还需要进一步研究。

RankUp 的五个机制是独立设计的，它们之间的协同效应和潜在冲突还没有被系统研究。特别是，随机置换分割和多 embedding 范式都在扩充初始表示多样性，它们是否存在冗余？

TokenFormer 的 SCP 现象在不同的统一建模架构（如 OneTrans、HyFormer、Kunlun）里是否同样存在？BFTS 和 NLIR 是否是对抗 SCP 的最优方案，还是存在更简洁的替代方案？

更根本的问题是：有效秩和最终的推荐性能（AUC、GMV）之间的关系是否是单调的？三篇论文都假设有效秩越高越好，但在某些场景下，适度的 collapse 可能有正则化效果，防止过拟合。这个假设的边界条件还需要更系统的研究。
