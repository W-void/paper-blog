arXiv Agent 论文近三个月总结（2025年12月–2026年3月）

数据来源：arXiv 实时检索整理时间：2026年3月15日

# 整体趋势总结

**Agent + RL 成为主流范式**：强化学习训练 Agent 是最热方向，但泛化性和工具使用仍是难题

**Multi-Agent 系统走向成熟**：分布式协作、通信协议、安全治理并行推进

**安全问题急剧升温**：数据泄露、对抗攻击、记忆操控成为新安全边界

**垂直落地加速**：医疗、金融、科研、运维各行业快速跟进 Agent 落地

**记忆机制是核心瓶颈**：长期记忆、动态更新、安全治理是多篇论文的核心议题

**评测体系仍不完善**：现有 benchmark 被批评过于结果导向，过程与决策质量评估滞后

**一句话总结**：Agent 要能做事（架构）→ 做复杂的事需要团队（Multi-Agent）
→ 持续做事需要记忆（Memory）→ 做事不能出错/被利用（安全）
→ 怎么训练才能做好事（RL）→ 在各行业真正落地（应用）
→ 怎么知道做得好不好（Benchmark）

# 一、Agent 基础架构与推理

## 动机

传统 LLM 的范式是"输入问题 → 输出答案"，本质上是被动的问答机。但现实世界的任务是开放的、动态的、多步骤的——需要 Agent 能够规划多步行动序列、感知环境状态变化、使用工具（搜索、执行代码、调用 API）、自我纠错并重新规划。因此研究者的核心动机是重新定义 LLM 的工作模式，从回答者变成行动者。技能模块化（Skill）方向的动机则是：避免每次靠 prompt 硬编码能力，让 Agent 像人类学技能一样积累可复用的程序知识。

# 二、多智能体系统（Multi-Agent Systems）

## 动机

单个 LLM Agent 在上下文窗口、专业能力、并行效率上均有天然限制。Multi-Agent 的核心动机是通过分工、协作、互相验证，突破单 Agent 的能力天花板。

一个有趣的反直觉发现是：若每个 Agent 都变得"太聪明、太自私"，在资源有限场景下反而产生竞争而非协作（类似"公地悲剧"）——这促使研究者思考 Multi-Agent 系统需要显式的协调机制和激励设计。博弈论视角的动机则是：现实中多 Agent 并非总是合作的，需要严谨理论框架来预测和设计行为。

# 三、Agent 记忆与状态管理

## 动机

当前 LLM 的上下文是一次性的——对话结束就消失了。这意味着 Agent 无法记住历史工作、无法从错误中学习、无法维护跨会话的项目状态。核心动机是让 Agent 像人类一样拥有持久化、可组织、可选择性召回的长期记忆，从"会话助手"升级为"长期伙伴"。

"记忆治理"方向的动机更进一步：错误的、被污染的记忆会让 Agent 持续犯错，甚至被恶意攻击者通过记忆注入来操控 Agent 的长期行为，因此需要安全、稳定的记忆更新机制。场论记忆的动机则来自认知科学：人类记忆是连续的、随时间自然衰退的，用 PDE 描述记忆在语义空间中的扩散可能更接近认知本质。

# 四、Agent 安全与对抗

## 动机

普通 LLM 只是"说话"，最坏情况是输出有害文字。但 Agent 能执行系统命令、发送消息、调用 API、读写数据库——一旦被攻击或误导，后果是真实的、不可逆的。随着 Agent 权限越来越大，安全问题变得极为紧迫。

各子方向的具体动机：

数据泄露：攻击者可通过网页嵌入隐藏指令，诱使高权限 Agent 将用户私有数据发出，研究者需揭示并防御这种新型攻击面

级联攻击：复合 AI 系统（多 LLM + 工具 + 数据库）的攻击面是叠加的，软硬件漏洞 + prompt 注入可组合成威力倍增的"攻击链"

具身 AI 安全：当 Agent 控制物理设备，安全漏洞可能造成真实物理伤害

# 五、Agent 训练与强化学习

## 动机

预训练让 LLM 掌握了知识和语言能力，但不意味着它天然擅长在真实环境中试错学习、知道"何时用工具/何时自己推理"、把长期目标分解成有效的短期行动。RL 的核心动机是通过与环境交互和奖励信号，让 Agent 习得适应性行为策略。

"信息自锁"这一发现尤其重要：RL 训练后的 Agent 倾向于"偷懒"——宁愿在内部反复推理（消耗 token），也不愿调用外部工具面对不确定性。这种行为在训练集上有奖励，但在真实任务中低效。研究动机是揭示这个隐患，为设计更好的 RL 目标函数提供依据。

Web Agent 数据自动生成的动机是数据瓶颈：训练 Agent 需要大量高质量操作轨迹数据，人工标注极贵，自动生成是唯一可扩展的路径。

# 六、垂直领域 Agent 应用

## 动机

通用 LLM Agent 在特定领域表现不如领域专家，因为缺乏领域特定的工具调用链、知识结构和合规约束。各垂直方向的具体动机：

医疗：临床工作流复杂、数据隐私敏感、决策错误代价极高，需专门设计 Human-in-the-loop 架构

材料科学：实验周期长、搜索空间巨大，Agent 可自动化"假设生成-实验设计-结果分析"全流程

金融：市场数据实时变化、多步推理、合规约束复杂，LLM 幻觉在金融场景代价巨大

智能合约审计：代码漏洞审计本质是多步推理+代码分析，人工成本极高，需精心设计 Agent 框架平衡效率与准确性

# 七、Benchmark 与评测

## 动机

如何知道一个 Agent 是真的"会做事"，还是只是在测试集上刷分？这是所有研究的元问题。核心矛盾在于：

现有 benchmark 多是孤立单步任务，而真实 Agent 任务是长链、开放的

现有评测只看最终结果，而 Agent 的决策过程同样重要

现有 benchmark 很快被刷穿，失去区分度

研究动机是建立更接近真实使用场景、更能区分真实能力的评测体系，让研究者知道自己的改进是实质性的还是过拟合的。
