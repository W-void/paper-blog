# Agent 记忆四大流派

## 流派1：RAG（检索增强记忆）

**核心思路**：记忆存向量库，用时检索相关片段塞进 context。

**代表作**：
- **MemGPT (2023)**：把 OS 分页思想搬进来，context = main memory，向量库 = disk。agent 自己决定什么时候 page in/out
- **RAPTOR (2024)**：把文档做多层摘要树，检索时可以粗粒度（摘要）也可以细粒度（原文）

**优点**：理论上记忆容量无限，和 LLM 解耦

**问题**：
- 检索精度是瓶颈——query 和 memory 语义不对齐时漏检
- "不知道自己不知道什么"——不检索就看不见
- 数学公式、代码片段向量化效果差

---

## 流派2：外部结构化存储

**核心思路**：不靠语义检索，而是用结构（key-value、图、文件系统）组织记忆。

**代表作**：
- **Mem0 (2024) **：自动抽取对话里的"事实"（用户偏好、名字、习惯），存 KV，精准检索
- **Zep**：用知识图谱存记忆，实体和关系显式建模

**优点**：精确，不依赖语义相似度，结构清晰

**问题**：
- 写入质量完全依赖 LLM 判断"这个值得记吗"——容易漏或者记太多
- 结构设计本身是难点（用 KV 还是图还是文件？）

---

## 流派3：压缩 + 分层（实际最主流）

**核心思路**：模仿人类记忆的工作记忆/长期记忆分层，对话历史定期压缩提炼。

**代表作**：
- **OpenClaw Compaction**：context 满了用 LLM 自动摘要
- **Claude Projects**：跨 session 的 instructions + knowledge 层
- **A-MEM (2025)**：借鉴 Zettelkasten，新记忆进来时不只是追加，还会回溯修改旧记忆、建立链接

**优点**：贴近人类认知，压缩后 context 更干净，工程最简单

**问题**：
- 信息损失不可逆——数字、代码、公式压缩后最容易出错
- 摘要粒度难把握：太粗丢细节，太细等于没压缩

---

## 流派4：参数化记忆（持续学习）

**核心思路**：不存外部，直接把知识微调进模型权重。记忆 = 模型本身。

**代表作**：
- **ROME / MEMIT (2022-2023)**：精准"编辑"模型里的某个事实，直接改权重
- **Larimar (2024)**：用 episodic memory module 辅助参数更新，减少灾难性遗忘

**优点**：推理时零额外开销，记忆和推理完全融合

**问题**：
- 灾难性遗忘：学新的忘旧的
- 成本极高，每次"记"新东西都要微调
- 记忆边界模糊：改了一个事实可能影响相关知识

---

## 横向对比

| 流派 | 容量 | 精度 | 成本 | 可解释性 | 实际普及度 |
|------|------|------|------|---------|----------|
| RAG | ∞ | 中 | 低 | 中 | ★★★☆ |
| 结构化存储 | ∞ | 高 | 低 | 高 | ★★☆☆ |
| 压缩分层 | 有限 | 中 | 低 | 中 | ★★★★ |
| 参数化 | 有限 | 高（会遗忘） | 极高 | 低 | ★☆☆☆ |

**现状**：context window 越来越长（Gemini 2.0 Flash 100万token），流派3优势会进一步扩大。
# LLM 上下文压缩方法汇总（2025.09 ~ 2026.03）

## 整体分类框架

上下文压缩按**压缩位置**分为三大类：

- **输入侧压缩**（Token Pruning）
- **中间层压缩**（KV Cache 压缩）
- **记忆侧压缩**（外部记忆管理）

---

## 一、Token 级别压缩（输入侧）

核心思路：在 prompt 进入模型之前删除冗余 token，减少 attention 计算量。

| 方法 | arXiv | 核心机制 |
|------|-------|---------|
| **Selective Context** | [2304.12102](https://arxiv.org/abs/2304.12102) | 基于 self-information（PPL）删除低信息量 token，经典基线 |
| **LLMLingua** | [2310.05736](https://arxiv.org/abs/2310.05736) | 粗粒度→细粒度两阶段，小模型打分大模型压缩（Microsoft） |
| **LLMLingua-2** | [2403.12968](https://arxiv.org/abs/2403.12968) | 数据蒸馏训练压缩器，速度提升 3~6x（Microsoft） |
| **PCRL** | [2406.18057](https://arxiv.org/abs/2406.18057) | RL 学 token 保留策略，感知下游任务 |
| **TACO-RL** | [2409.13035](https://arxiv.org/abs/2409.13035) | REINFORCE + 下游任务 reward，端到端训练压缩器；**最优实践之一** |

**TACO-RL 要点**：不依赖规则/启发式，直接优化"压缩后任务表现"；支持可变压缩率；在 RAG 场景下效果显著。

---

## 二、KV Cache 压缩（中间层）

### 2a. 静态/固定策略（经典方法）

| 方法 | arXiv | 核心机制 |
|------|-------|---------|
| **StreamingLLM** | [2309.17453](https://arxiv.org/abs/2309.17453) | 永远保留前几个 token（sink tokens）+ 滑窗，支持无限序列推理 |
| **H2O** | [2306.14048](https://arxiv.org/abs/2306.14048) | Heavy-Hitter Oracle：只保留 attention score 累计最高的 KV |
| **SnapKV** | [2404.14469](https://arxiv.org/abs/2404.14469) | 以 prompt 末尾 query 为锚点选 KV，适合 QA 场景 |

### 2b. 动态/任务感知策略（2025 主力方向）

| 方法 | arXiv | 核心机制 |
|------|-------|---------|
| **PyramidKV** | [2501.01478](https://arxiv.org/abs/2501.01478) | 浅层留多（全局信息），深层压缩（局部注意力），层级差异化保留 |
| **KVSharer** | [2503.05919](https://arxiv.org/abs/2503.05919) | 跨层共享 KV，相邻层 KV 高度相似，合并后不掉精度 |
| **MagicPIG** | [2410.16179](https://arxiv.org/abs/2410.16179) | LSH 近似 TopK attention，避免全量 attention 计算 |
| **ClusterKV** | [2412.03213](https://arxiv.org/abs/2412.03213) | 对 Key 聚类，用聚类中心代替原始 KV，保持语义多样性 |
| **RazorAttention** | [2410.23168](https://arxiv.org/abs/2410.23168) | 识别"检索头"（Retrieval Head），只对检索头做全量 attention，其余压缩 |

**2025 趋势**：不是均匀删 KV，而是**区分 head 类型/层级，差异化保留**。

---

## 三、软压缩 / 压缩到向量（Soft Compression）

核心思路：不删 token，而是把长文本编码成少量"压缩向量"，作为 prefix 输入。

| 方法 | arXiv | 核心机制 |
|------|-------|---------|
| **Gist Tokens** | [2304.08467](https://arxiv.org/abs/2304.08467) | 训练特殊 \<GIST\> token 吸收上下文信息，经典基线 |
| **AutoCompressor** | [2305.14788](https://arxiv.org/abs/2305.14788) | 递归压缩，每段产出 summary vector，传入下段 |
| **ICAE** | [2406.00888](https://arxiv.org/abs/2406.00888) | Encoder-Decoder 架构，压缩率可达 4~15x |
| **xRAG** | [2405.13792](https://arxiv.org/abs/2405.13792) | 压缩 retrieval 文档为单向量注入，专为 RAG 优化 |
| **CompAct** | [2501.14954](https://arxiv.org/abs/2501.14954) | 把 retrieved passage 压缩为 activation，注入 cross-attention |

**局限**：需要专门训练/微调，泛化性弱；黑盒 API 无法使用。

---

## 四、摘要 + 外部记忆（长对话场景）

核心思路：对话历���不在 context 里存原始文本，而是压缩成摘要/向量存外部记忆。

| 方法 | arXiv / 来源 | 核心机制 |
|------|------------|---------|
| **MemGPT** | [2310.08560](https://arxiv.org/abs/2310.08560) | Hierarchical memory（内存/外存切换），LLM 自主管理记忆，经典 |
| **ReadAgent** | [2402.09727](https://arxiv.org/abs/2402.09727) | Gist Memory：先分段精读产出 gist，再按需 look-up（Google） |
| **SCM** | [2412.08821](https://arxiv.org/abs/2412.08821) | Scarce Context Management，RL 驱动的周期性摘要，学习"什么时候压缩" |
| **RecurSumm** | [2501.09276](https://arxiv.org/abs/2501.09276) | 递归摘要，每轮新信息 + 旧摘要 → 新摘要，轻量无需训练 |
| **A-MEM** | [2502.12110](https://arxiv.org/abs/2502.12110) | Agent Memory：Zettelkasten 风格，每条记忆有 link/decay |

**2025 方向**：从"硬规则触发摘要"到"RL 学习最优压缩时机"。

---

## 五、训练阶段方案（长上下文原生支持）

| 方法 | arXiv | 核心机制 |
|------|-------|---------|
| **YaRN** | [2309.00071](https://arxiv.org/abs/2309.00071) | RoPE NTK-aware 插值，支持 128K+ context 外推 |
| **LongRoPE** | [2402.13753](https://arxiv.org/abs/2402.13753) | 非均匀位置插值 + 渐进式训练，支持 2M context |
| **LongLoRA** | [2309.12307](https://arxiv.org/abs/2309.12307) | 训练时用 Shifted Sparse Attention，推理时恢复全量 attention |
| **Ring Attention** | [2310.01889](https://arxiv.org/abs/2310.01889) | 多设备分布式 attention，理论上支持无限序列 |
| **Mamba** | [2312.00752](https://arxiv.org/abs/2312.00752) | 状态空间模型，O(n) 替代 Transformer O(n²)，天然支持长序列 |

## 六、评估指标体系

### Token 压缩 / 软压缩

- **下游任务精度**（最核心）：QA 用 EM/F1，摘要用 ROUGE，代码用 Pass@k
- **压缩率**（Compression Ratio）：通常报 4x / 8x / 15x
- **精度-压缩率 tradeoff 曲线**：面积越大越好

### KV Cache 压缩

- **困惑度（Perplexity）**：压缩前后 PPL 差距
- **KV Budget 下的精度**：5% / 10% / 20% budget 对应精度
- **显存占用 / 吞吐量**：GPU Memory (GB)、Tokens/sec

### 记忆/摘要压缩

- **信息保留率**（用 QA 代替）：关键事实能否从摘要中还原
- **多轮对话一致性**
- **Human Evaluation**：一致性 / 相关性 / 流畅度（5分制）

### 常用 Benchmark

| Benchmark | 考察点 |
|-----------|--------|
| **LongBench** | 长文档多任务（QA/摘要/代码/Few-shot） |
| **RULER** | 对抗性长上下文（Needle-in-haystack 变种） |
| **InfiniteBench** | 100K+ 极端长度，考察真正的记忆能力 |

### ⚠️ 共同短板（2025 年争议点）

1. **压缩率虚报**：未算软压缩 encoder 的推理开销
2. **任务分布偏差**：LongBench 上好看，换成真实 Agent 对话就崩
3. **Needle-in-Haystack 被玩烂了**：很多方法专门针对此 benchmark 调参
4. **缺乏端到端延迟评估**：光报精度不报推理速度

---

## 七、最优实践组合（2026 工程实践）

**推理阶段（无需训练）**：

- PyramidKV（层级 KV 压缩）
- \+ RazorAttention（区分 head 类型）
- \+ 外部摘要记忆（长对话）

**训练阶段（有 fine-tune 条件）**：

- TACO-RL / PCRL（任务感知 token 压缩）
- \+ xRAG / CompAct（RAG 文档软压缩）

---

| 维度 | 2024 主流 | 2025-2026 趋势 |
|------|---------|---------------|
| KV 压缩策略 | 均匀保留 top-K | 层级/头类型差异化 |
| Token 压缩 | 规则/启发式 | RL 任务感知 |
| 记忆管理 | 固定规则触发摘要 | RL 学习最优压缩时机 |
| 软压缩 | 需大量微调 | 轻量注入，专为 RAG 优化 |

## 大白话解读：各方法在干什么？

### 🔪 第一类：Token 压缩（直接删 token）

**StreamingLLM**

发现模型特别依赖「第一个 token」（称为 attention sink），所以策略是：永远保留开头几个 + 最近 N 个，中间的全删。简单粗暴，推理速度快，适合超长流式对话。

**H2O（Heavy-Hitter Oracle）**

统计哪些 token 被 attention 关注最多（「重度用户」），只保留这些 KV Cache，其余淘汰掉。本质是让模型自己投票决定谁重要。

**SnapKV**

发现 query 的 attention 模式在整个序列里很稳定，用它来提前预测哪些 KV 值值得留，不用等跑完整推理才知道删谁。速度比 H2O 快。

**PyramidKV**

不同 Transformer 层关注的信息范围不同——浅层看局部细节、深层看全局语义。所以浅层多保留 KV、深层少保留，按金字塔形分配 Cache 预算，比均匀分配更高效。

**LLMLingua / LLMLingua-2**

用一个小语言模型给每个 token 打「重要性分数」，低分 token 直接从 prompt 里删掉再喂给大模型。压缩率很高，适合超长 RAG 检索结果的 prompt 压缩。

**PCFG Prompt Compression**

把 prompt 当成一棵语法树来分析，按短语/子句粒度决定保留还是删除，比 token 级剪裁保留了更多语义完整性。

### 🗃️ 第二类：KV Cache 管理（不删 token，管内存）

**MagicPIG / Quest**

不是删 KV，而是「按需检索」：每次只把当前 query 真正需要的 KV 调出来参与计算，用 LSH/稀疏索引加速查找。像给 KV Cache 建了个数据库索引，GPU 内存占用大幅下降。

**CLA（Cross-Layer Attention）**

相邻层的 KV Cache 高度相似，干脆让多层共享同一份 KV，显著压缩内存占用，推理速度提升。不需要重新训练，改架构即可。

**GQA（Grouped Query Attention）**

多个 Query head 共享一组 KV head，是现在 LLaMA/Mistral 等主流模型的标配。本质是在模型结构层面做 Cache 压缩，推理吞吐提升显著。

**Ring Attention / Striped Attention**

把超长序列切成块，分布在多个设备上并行处理，设备间以流水线方式传递 KV。解决的问题是单卡放不下超长序列的内存问题。

### 🧬 第三类：软压缩（把长文本压成几个向量）

**AutoCompressor**

把长上下文喂给模型，让它输出几个「摘要向量」，后续对话只用这些向量。就像把一本书压成几个关键词向量——人看不懂，但模型懂。压缩率极高，训练成本适中。

**Gist Token**

在 prompt 里插入特殊占位 token，训练模型把所有上下文信息「灌」进这几个 gist token，之后丢掉原始 prompt 只用这些 token。压缩率高，但依赖特定训练。

**ICAE（In-Context AutoEncoder）**

专门训练一个压缩器模型，把长文档编码成极短的「记忆槽」（比如 512 个 token → 32 个向量）。压缩率业界最高，但只能配合特定解码器使用，迁移性差。

**xRAG**

专为 RAG 场景设计的软压缩：把检索回来的文档片段压成几个向量注入给生成模型，让生成模型不需要在 context 里看完整文档。

### 📝 第四类：摘要记忆（用语言本身来压缩）

**MemGPT**

模拟操作系统的内存管理：有「工作内存」（当前对话窗口）和「外部存储」（历史摘要），模型自己决定什么时候把内容存到外存、什么时候调回来。适合超长多轮对话场景。

**RecurrentGPT**

每轮对话结束后，让模型写一段「长期记忆摘要」，下轮只带摘要 + 最近几轮，不带完整历史。直觉上最自然，类似人类「大概记住之前说了啥」。

**TACO-RL**

用强化学习训练压缩策略：模型自己学「什么时候该摘要、摘多少」，奖励信号是下游任务表现。不是人工规定的固定策略，更灵活。

**Compress-then-Reason**

先用小模型对上下文去噪压缩，再让大模型在压缩后��内容上推理。分工明确：小模型负责过滤噪声，大模型专注推理，两者各司其职。

### 🏋️ 第五类：训练方案（从根上解决长上下文问题）

**RoPE Scaling（YaRN / LongRoPE）**

原始 RoPE 位置编码在超出训练长度后会「失灵」，这些方法通过数学变换（缩放/插值）让模型能处理比训练时长得多的序列，不用重新从头训练。YaRN 是目前最常用的方案之一。

**LongLoRA**

用极少的算力（LoRA 参数微调）让模型处理超长上下文。核心技巧：训练时用「移位注意力」（shift short attention）模拟长距离依赖，推理时恢复完整 attention。资源友好。

**CEPE（Context Expansion via Parallel Encoding）**

把长文档切块分别编码，再用 cross-attention 拼起来。模型本体不变，只加一条旁路来处理超长输入，对原始模型侵入性小。

**任务感知 Token 剪裁（Task-Aware Pruning）**

不同任务需要的上下文完全不同（摘要任务 vs 代码生成所需的 token 几乎没有交集），所以训练一个「知道当前任务是什么」的剪裁器，为不同任务定制保留策略，比通用剪裁效果好得多。
