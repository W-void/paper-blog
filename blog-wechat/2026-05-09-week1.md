## 方向性归纳

### 一、生成式推荐：Semantic ID 的多维困境与突破

这是本周最热的方向，论文不仅多，而且相互构成了对同一问题的不同侧面的攻坚。

**[Expressiveness Limits of Autoregressive Semantic ID Generation in Generative Recommendation](https://arxiv.org/abs/2605.06331)**

UCSD/Snap 这篇从理论层面戳破了一个被忽视的根本缺陷：自回归 SID 解码会形成一棵树，树上路径相近的 item 概率被强制耦合，模型**无法区分 SID 前缀相同但用户偏好差异极大的两个 item**。修复方案 Latte 在每个 SID token 前插入潜变量，将单棵树变成"多棵条件树"，打破概率耦合，NDCG@10 平均提升 3.45%。

**[CapsID: Soft-Routed Variable-Length Semantic IDs for Generative Recommendation](https://arxiv.org/abs/2605.05096)**

比 Latte 更根本地换了 tokenizer：用胶囊软路由（iterative routing）替代 RQ-VAE 的硬最近邻量化，每个 item 可以"软属于"多个语义胶囊，解决边界语义坍塌和错误传播；再配上 SemBPE（类比 NLP 中的 BPE）把常见 ID 对合并为子词，在 3500 万物品工业数据集上 Recall@10 相比 ReSID 提升 9.6%，推理延迟仅为 COBRA 的 51%。

**[TriAlignGR: Triangular Multitask Alignment with Multimodal Deep Interest Mining for Generative Recommendation](https://arxiv.org/abs/2605.05249)**

从另一个角度诊断 SID 的问题：RQ-VAE 压缩会让 SID 丢失视觉语义（SCD），且模型会"背"SID 但不理解其含义（SSO）。TriAlignGR 构建 SID-Text-Image 三角互监督框架，用 VLM 注入视觉信息，用 LLM CoT 挖掘隐式兴趣语义，8 个互补生成任务共享 decoder 权重，无需额外 task tower。

**[Unified Value Alignment for Generative Recommendation in Industrial Advertising (UniVA)](https://arxiv.org/abs/2605.05803)**

生成式推荐进工业广告的落地难题：推荐目标是"内容相关性"，广告目标是 GMV/eCPM，二者在 tokenization、解码、在线服务三个阶段各自割裂。UniVA 三管齐下——Commercial SID Tokenizer 在 token 构建时注入价值属性，Generation-as-Ranking Decoder 用 eCPM 感知 RL 让生成即排序，Value-Guided Beam Search 用个性化 trie 限制解码路径。腾讯微信视频号广告线上 A/B：Hit Rate@100 离线提升 37.04%，GMV 在线提升 1.5%。

### 二、LLM 融合推荐：对齐、端侧与贝叶斯

**[BLADE: Beyond Static Best-of-N: Bayesian List-wise Alignment for LLM-based Recommendation](https://arxiv.org/abs/2605.04559)**

LLM 推荐的列表级对齐一直是痛点——BoN（Best-of-N）对齐随着模型越来越强，参考分布逐渐"跟不上"，梯度信号衰减。BLADE 引入贝叶斯框架，将历史先验和当前模型 rollout 融合为动态目标分布，让训练目标随模型能力进化，直接优化 NDCG、公平性等列表级指标，在 3 个数据集上**突破了静态 BoN 的性能上界**。SIGIR 2026 接收。

**[RecGPT-Mobile: On-Device LLMs for User Intent Understanding in Taobao Feed Recommendation](https://arxiv.org/abs/2605.04726)**

云端 LLM 延迟高、成本贵的工程困境，阿里淘宝给出端侧解法：把轻量级 LLM 直接部署到用户手机，实时分析近期行为预测 next-query，将意图信号实时注入推荐系统。无网络往返延迟、用户数据不出设备、实时捕捉兴趣漂移，淘宝 Feed A/B 测试验证可行。

### 三、序列推荐与协同过滤：扩散模型的定制化

**[StageCF: Interests Burn-down Diffusion Process for Personalized Collaborative Filtering](https://arxiv.org/abs/2605.05165)**

扩散模型进推荐的一个基本问题：为什么要套用图像生成的高斯噪声？用户兴趣衰减有语义规律，不是随机噪声。StageCF 专门设计"兴趣燃烧衰减"正向过程（Burn-down），对应地做"燃烧复苏"的逆向推理（Burn-up），并用个性化图网络建模不同用户对不同类别的差异化衰减速率。

**[ConvRec: Rethinking Convolutional Networks for Attribute-Aware Sequential Recommendation](https://arxiv.org/abs/2605.04723)**

序列推荐不一定要用 Transformer。ConvRec 用层级下采样卷积（每层 AvgPool1d 将序列压缩一半），实现线性复杂度 O(n) 的序列建模，在 4 个真实数据集上超越 SASRec、BERT4Rec，运算开销更低。IJCAI 2026 接收。

### 四、跨域推荐：时序感知与语义迁移

**[BST-CDSR: Bridging Behavior and Semantics for Time-aware Cross-Domain Sequential Recommendation](https://arxiv.org/abs/2605.02369)**

跨域推荐被忽视的两个维度：不同域的时间节奏不同（电影每天刷，书一个月买一本），且语义偏好也会随时间变化。BST-CDSR 用 Neural ODE 建模连续时间偏好演化（不是离散时间步），用 LLM 生成时序感知语义表示并引入时序反事实增强对比学习，门控机制控制跨域迁移权重避免负迁移。

**[FEDIN: Frequency-Enhanced Deep Interest Network for CTR Prediction](https://arxiv.org/abs/2605.01726)**

从频域视角重看用户兴趣建模：真实兴趣的注意力在频域呈低熵（集中尖峰），噪声行为呈高熵（分散）。FEDIN 对用户行为序列做 FFT，目标感知地过滤高熵噪声，在 Amazon Books / MovieLens-1M / Taobao 上 AUC 提升 0.3%~0.8%。SIGIR 2026 接收。

### 五、工业落地优化：多任务、剪枝与系统加速

**[Effective Knowledge Transfer for Multi-Task Recommendation Models (EKTM)](https://arxiv.org/abs/2605.05730)**

CVR 数据稀疏导致模型训练不稳定的经典问题。EKTM 用 Router-Transmitter-Enhanced 三模块框架，从"共享知识池"中为每个 CVR 任务独立提取相关知识，避免负迁移。Router-Transmitter 解耦设计比 PLE 更显式地建模知识传递方向，已在商业平台全量上线，**eCPM 提升 3.93%**。华为诺亚方舟实验室。

**[Light-FMP: Lightweight Feature and Model Pruning for Enhanced Deep Recommender Systems](https://arxiv.org/abs/2605.06441)**

三阶段剪枝框架解决特征维度爆炸问题：预训练阶段用 Hard Concrete Distribution 学习二值掩码（近似离散特征选择，可微），剪枝阶段同时剪模型结构与特征，继续训练阶段用剩余数据微调。Hard Concrete 与 L1 软剪枝不同，能实现真正的稀疏化。

**[HELM: One Pool, Two Caches: Adaptive HBM Partitioning for Accelerating Generative Recommender Serving](https://arxiv.org/abs/2605.04450)**

生成式推荐系统部署侧的独特难题：Embedding 热缓存（EMB）和 KV 缓存争抢 GPU HBM，最优分配比在不同负载下相差高达 0.35，静态分配浪费 20-30% 延迟优化空间。HELM 用三层 PPO 控制器（冻结基础策略+在线残差适配器+突发感知恢复）实时调整分配比���决策延迟仅 32μs，在 32 节点 A100 集群上 P99 延迟降低 24-38%。

### 六、推荐公平性：适配器与多智能体框架

**[PFA: Post-hoc Provider Fairness Adaptation via Hierarchical Exposure Alignment](https://arxiv.org/abs/2605.01524)**

在冻结的推荐模型上插一个轻量级"公平适配器"（N 层 MLP），学习每个 item 的分数调整量，使提供者曝光分布更公平。层次化公平对齐损失（HEFA）同时处理组间和组内的曝光不均衡。想换公平性目标只需重训适配器，无需动主模型，NDCG 下降 < 0.5%。

**[Fair Agents: Balancing Multistakeholder Alignment in Multi-Agent Personalization Systems](https://arxiv.org/abs/2605.02379)**

LLM 智能体驱动的多方个性化系统的公平对齐框架（UMAP 2026 Workshop），引入社会选择理论（Borda Count、Nash Bargaining）聚合多智能体输出，设计组合评估体系。当前是概念框架，但方向值得关注。

### 七、RAG 与检索：可靠性与 Agentic 检索

**[RAG over Thinking Traces Can Improve Reasoning Tasks](https://arxiv.org/abs/2605.03344)**

一个视角转换的工作：不检索文档，检索"别人解题时的思维轨迹"。T3（Thinking Trace Transformation）将原始思维链转化为结构化、检索友好的表示。使用 Gemini-2-thinking 生成的轨迹辅助 Gemini-2.5-Flash，在 AIME 上相对提升 **+56.3%**，推理成本降低最多 15%。

**[SURE-RAG: Sufficiency and Uncertainty-Aware Evidence Verification for Selective RAG](https://arxiv.org/abs/2605.03534)**

RAG 的一个深层问题：检索到的文档"各自相关"但"合起来还是不够用"（多跳推理）。SURE-RAG 做集合级证据充分性验证，输出三路决策，在 HotpotQA-RAG v3 上 Macro-F1 达 0.9075，远超 DeBERTa（0.6516）和 GPT-4o judge（0.7284）。IEEE PRAI 2026。

**[GenPOI: Revisiting General Map Search via Generative Point-of-Interest Retrieval](https://arxiv.org/abs/2605.03397)**

腾讯地图把生成式推荐思路移植到 POI 检索：将 POI 用 VQ-VAE 量化为离散 token（同时编码语义和地理 GeoHash），把检索变成序列生成任务，邻近感知约束生成保证地理合理性。在千万级 POI 工业数据集上，模糊查询召回率显著提升。

## 横向对比：洞察与趋势

### 生成式推荐：从"哪里坏了"到"怎么修"的多路攻坚

本周最值得关注的是生成式推荐方向的**集中爆发**。四篇论文（Latte、CapsID、TriAlignGR、UniVA）从不同维度诊断并修复了 Semantic ID 的结构性缺陷：

- **Latte**（表达能力上界）和 **CapsID**（量化方式）是从理论/机制层面在 SID 生成这一根本环节动刀，思路互补——Latte 解决了解码空间的概率耦合，CapsID 解决了量化过程的语义坍塌；
- **TriAlignGR** 则是在"SID 语义质量"上发力，认为根本问题是 SID 不够"有内涵"，通过三角对齐补全多模态语义；
- **UniVA** 则面向工业落地，聚焦价值对齐——前三篇解决的是"推荐质量"问题，UniVA 解决的是"推荐目标"问题。

这四篇合在一起，实际上画出了生成式推荐走向成熟落地所需跨越的障碍图。

### LLM 推荐：从"能用吗"到"怎么用好"

BLADE 和 RecGPT-Mobile 代表了两种截然不同的技术路线：前者是在云端对 LLM 推荐的对齐目标做精细化（贝叶斯动态目标），后者是用端侧部署绕开工程瓶颈。两者都在解决"LLM 推荐落地"的问题，只是一个卷的是训练范式，一个卷的是部署架构。值得注意的是，RecGPT-Mobile 的端侧路径在隐私保护、实时性上有独特优势，但模型压缩带来的精度损失如何与推荐质量权衡，论文并未给出详细分析。

### 扩散模型 vs 传统序列模型：卷 Transformer 还是卷噪声过程？

StageCF 和 ConvRec 选了两条反方向的路：StageCF 用定制化扩散过程（替代高斯噪声）深化推荐建模，ConvRec 用卷积架构（替代 Transformer）降低复杂度。两者都在质疑"把图像领域方法直接搬来"的做法。StageCF 的个性化衰减图网络和 ConvRec 的层级下采样在工业场景的可扩展性仍需验证，但提供了清晰的研究思路。

### RAG：从"能检索"到"能用于推理"

RAG over Thinking Traces 是本周 RAG 方向最有洞察的工作——它指出了 RAG 在推理任务上低效的根本原因：文档不是推理的最小单元，思维轨迹才是。这和 SURE-RAG 的集合级充分性判断一起，代表了 RAG 从"检索-生成"管道向"真正支持推理"演进的两个关键环节：一是检索什么（轨迹 vs 文档），二是检索够不够（充分性验证）。
