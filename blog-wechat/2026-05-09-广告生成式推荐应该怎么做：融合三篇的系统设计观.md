# 广告生成式推荐应该怎么做：融合三篇的系统设计观

## 背景：推荐系统正在经历一次范式迁移

传统的广告推荐系统是一条流水线：先由召回模块从千万量级的广告库里快速筛出几百个候选，再由粗排模块做初步打分，最后由精排模块精细计算每个候选的 eCPM（千次展示收益）。这条流水线在工业界跑了十几年，每一级都有成熟的工程积累。

但它有一个根本性的结构缺陷：早期被召回模块丢掉的广告，后续所有模块都无法再找回来。召回模块追求速度，用的是粗糙的相似度估计，不可避免地会漏掉一些召回得分普通但实际价值很高的广告。而这个损失，精排模块再强也无法弥补，因为它根本看不到那些在召回阶段就消失的候选。

另一个问题是各阶段优化目标不一致。召回追覆盖率，精排追 eCPM，中间还有若干过渡目标——三个阶段各自优化，但没有一个统一的端到端目标把它们串起来。

生成式推荐（Generative Recommendation，GR）提供了一种根本不同的思路。它不做"从候选集里打分选出最好的"，而是做"直接生成用户最可能感兴趣的广告是什么"。具体实现是：给每个广告分配一串离散的语义编码（称为 Semantic ID，SID），训练一个自回归语言模型，给定用户历史逐层生成这串编码。这样就把推荐问题改写成了"下一个 token 预测"，一个模型端到端完成原来三个阶段的全部工作。

这套范式在内容推荐（刷短视频、看文章）里已经被证明可以跑赢传统流水线。但广告系统有额外的要求：广告主在出价，平台要考虑 eCPM，用户体验也要顾及——仅靠"生成用户喜欢的内容"是不够的，还需要同时生成"商业价值高"的广告。如何把商业价值信号融入生成式推荐的全链路，就是本文要讨论的核心问题。

以下的分析综合了三篇工业论文的设计与实验：腾讯微信视频号的 GPR（GMV 累计提升 5%+）、腾讯 UniVA（GMV 提升 1.5%）、快手的 GR4AD（广告收入提升 4.2%）。三篇都已在亿级用户规模的真实广告系统全量部署。

## 第一个问题：怎么给广告编码

GR 的第一步是给每个广告分配一串 SID。这串编码必须同时满足两个看似矛盾的要求：语义上相似的广告应该有相近的编码（这样模型才能泛化），但商业属性不同的广告必须有可区分的编码（否则模型无法区分高价值和低价值候选）。

### 标准做法是什么

把广告的多模态信息（视频帧、标题文字、商品图）用一个预训练模型压缩成一个高维向量，再用残差量化（Residual Quantization，RQ）把这个向量逐层离散化。RQ 的工作方式类似于用一套层级地址描述一个位置：第一层给出大区（华北），第二层给出城市（北京），第三层给出街道（朝阳路）。最终每个广告得到一串 L 个离散符号，比如 [42, 7, 391]，这就是它的 SID。

模型的任务变成：给定用户历史行为序列，自回归预测下一个感兴趣广告的 SID——先预测第一层的符号是什么，再以第一层为条件预测第二层，再预测第三层。三步预测完，就唯一确定了一个具体的广告。

### 纯语义编码的根本缺陷

问题在于，语义相似的广告在 SID 空间里会被量化到同一条路径，但商业属性可能天差地别。一个视频素材相同的广告，由不同广告主投放时，出价可以相差十倍；同一个广告主投放的两个广告，转化目标（品牌曝光 vs 直接购买）也可能完全不同。如果这些广告共享了同一条 SID 路径，模型就无法区分它们，beam search 探索"手机类广告"这个分支时，高价值和低价值广告对模型来说是一样的。

GR4AD 给出的数字很直观：用纯语义量化时，SID 碰撞率（不同广告被分配到同一条 SID 路径）高达 85.44%，也就是说，平均每 7 个广告里有 6 个是"撞号"的，模型根本分不清它们。

### 解法：最后一层改用确定性映射

三篇论文都独立得出了同一个结论：语义量化可以在前几层保留，但最后一层应该放弃向量量化，改用确定性映射把业务属性直接编码进去。

GR4AD 的做法是 hash 映射：把"转化类型 + 广告账户 ID"组合 hash 成一个确定性的 token。相同素材、不同广告主的两个广告，在前两层可能完全一样（语义相近），但在最后一层会落到不同的 token，彻底消除碰撞。这把碰撞率从 85.44% 压到了 18.26%。

UniVA 的做法类似，但编码的是价值维度：把"优化目标 × ROI 目标 × 行业"组合成一个商业 Key，在 Key 内部按出价做等频分桶（保证每个桶里的广告数量大致相同）。这样同一条完整 SID 路径里的广告，不仅内容相近，出价也集中在同一个价格区间。

两种做法编码的业务属性维度不同，但原则相同：对于广告系统里那些语义相同但业务属性不同的广告，必须用确定性编码而不是可学习量化来区分它们。这两个维度（身份标识和价值区间）也可以同时编码，不互斥。

### 底座嵌入的重要性被低估

在讨论量化方案之前，还有一个更基础的问题经常被忽略：向量量化的质量上限取决于被量化的向量本身有多好。广告是一个多模态混合体——短视频画面、商品标题、广告主意图、投放设置——任何单模态嵌入都只能覆盖其中一部分语义。

GR4AD 用 Qwen3-VL-7B 做底座，专门针对广告的六种类型（直播、商品视频、虚拟产品等）写了指令调优模板，还加入了共现学习：如果两个广告在大量用户的历史里频繁共现（买同一类东西的用户倾向于同时点击这两个广告），就在嵌入空间里让它们靠近。这一步让 photo-to-photo recall 从 0.541 跳到 0.896。

这个数字说明：量化方案的精细调参，带来的收益远不如底座嵌入的质量提升显著。先把广告的"理解"做好，再量化。

## 第二个问题：模型结构怎么设计

给广告编好码之后，需要一个模型来学习"给定用户历史，预测下一个 SID"。广告系统的输入天然是异构的，这个特性对模型结构有很强的约束。

### 广告系统输入的异构性

一个广告请求到来时，模型需要理解的信息至少有四类：用户的基础画像（年龄、性别、兴趣标签）、用户最近的有机内容行为（刷了哪些视频、看了哪些文章）、用户的历史广告交互（过去点击或转化过哪些广告）、以及当前请求的上下文（设备类型、时段、广告位）。

这四类信息的语义空间差异很大。用户画像是静态的结构化特征，有机内容行为是内容语义，广告交互是商业行为，请求上下文是环境元信息。如果把这四类 token 送进同一套参数处理，它们会在 FFN 层和 LayerNorm 层相互干扰——每类 token 的特征分布不同，共享归一化参数意味着用同一把尺子量四种完全不同的东西。

GPR 给这四类 token 各自配置了独立的 FFN 和 LayerNorm 参数（Token-Aware FFN/LN），这一个改动在消融实验里贡献了 +15.8% HitR@100，是论文里所有单组件增益最大的一个。异构 token 的参数干扰是一个真实的性能瓶颈，而且修复成本很低——只是把共享参数改成分组参数，不需要改变任何网络结构。

### 单解码器 vs 双解码器

GPR 把模型拆成了两个解码器：一个主干解码器（HSD）专门处理用户历史理解，输出一个"用户意图嵌入"；另一个轻量解码器（PTD）以这个意图嵌入为条件，专门做 SID 的自回归生成。理论上，理解任务更适合双向注意力（因为上下文可以互相参考），而生成任务必须用因果 mask（不能看到未来的 token）——两个任务对注意力机制的需求本来就不同，分开处理更合理。

但 GR4AD 和 UniVA 用的都是单解码器，同样在真实系统里取得了好结果，GR4AD 甚至实现了 <100ms 时延和 500+ QPS/L20 的工程指标。所以"双解码器一定比单解码器好"这个结论并没有跨系统的证据支撑。在 serving 延迟预算紧张的场景下，单解码器 + Token-Aware FFN/LN 是更务实的起点。

### 一个值得关注但还不成熟的设计：Thinking Tokens

GPR 在 SID 生成之前，让模型先生成若干个"思考 token"——这些 token 不对应任何广告，只是在隐空间里给模型提供一个"先想清楚用户想要什么"的缓冲区，然后再基于这个澄清过的意图做 SID 生成。这个设计贡献了 +14.6% HitR，是 GPR 里仅次于 Token-Aware FFN/LN 的单组件增益。

直觉上，这解决的是一个真实问题：用户意图经常是模糊的、多义的。一个用户历史里同时有手机、耳机、充电器的交互，这次请求到来时他最可能感兴趣的是哪类广告？直接把历史序列接到 SID 生成上，模型没有足够的"思考空间"来分解这个意图，而 Thinking Tokens 提供了这个空间。

这个设计目前只有 GPR 一篇验证，缺乏跨系统的证据，所以还不能作为普遍建议。但 +14.6% 这个数字足以说明它值得在自己的系统里验证。

### 一个常被忽视的设计原则：显式切断不该互相影响的梯度

GPR 的 HTE（用来在 beam search 里估算每个候选的 eCPM）用了一个 stopgrad——价值估算头的梯度不会反传到主干解码器。这看起来只是一个实现细节，背后实际上是一个更普遍的原则：在多目标共享参数的系统里，"各自的 loss 各管各的"这个直觉是错的。梯度反传时，每个 loss 都会影响所有与之相连的共享参数。如果价值估算目标和生成目标对同一份表示有不同的偏好，它们的梯度会在共享参数里相互拉扯，这是多任务学习里"负迁移"的来源之一。需要根据目标的性质，显式决定哪些梯度流应该被切断。

## 第三个问题：怎么训练

GR 的训练不是一步到位的，三篇论文都收敛到了类似的三阶段结构，每个阶段解决一个特定的问题。

### 第一阶段：让模型先学会"用户会点什么"

这一阶段用监督学习，从历史日志里学习用户行为模式。输入是用户历史序列，监督信号是用户下一个交互的广告 SID。这一阶段的目标是建立稳定的生成能力，让模型对用户兴趣有基础的理解。

一个具体的优化是 GPR 的 MTP（Multi-Token Prediction）：标准做法只预测用户下一个感兴趣的广告（一条兴趣线），但真实用户在同一时刻往往同时有多条并行的兴趣。用 4 个独立的预测头，在同一个 backbone 状态上同时预测 4 条不同的兴趣路径，4 条路径的 loss 都用来更新参数，倒逼 backbone 表示得更全面。这个改动带来了 +17.9% HitR，是三篇所有组件里单组件增益最大的数字，而且实现成本低——只是在 backbone 顶端加了 3 个额外的预测头。

### 第二阶段：把商业价值信号注入梯度

第一阶段的监督学习对所有历史样本一视同仁——用户点击了一个出价 1 元的广告和点击了一个出价 100 元的广告，产生的梯度是一样大的。但广告系统关心的是商业价值，低价值广告贡献了大量训练样本（因为数量多），却不应该获得过多的梯度权重。

GPR 的 VAFT（Value-Aware Fine-Tuning）做的事情很直接：在原来的 loss 上乘一个权重系数，这个系数同时考虑行为类型（转化 > 点击 > 曝光）和 eCPM 量级。具体来说，转化样本的权重是 eCPM/(pCTR×pCVR)，点击样本的权重是 eCPM/pCTR，曝光样本的权重直接是 eCPM。这样，一次高 eCPM 的转化行为能获得的梯度，远大于一次低 eCPM 的曝光行为。模型的"注意力"从均匀分布在所有历史行为，逐渐偏向高价值行为。

这一步必须在第一阶段之后做。如果第一阶段还没建立稳定的生成能力就引入强价值权重，高 eCPM 样本的稀疏性（这类样本在训练数据里占比很少）会让梯度方差过大，训练不稳定。

### 第三阶段：用强化学习探索历史日志之外的高价值路径

前两个阶段有一个根本性局限：模型只能从历史日志里学，而历史日志记录的是过去系统的决策。对于那些历史上从来没被推荐过、但如果推荐了用户可能会喜欢的广告，监督学习完全看不到它们。这是一个覆盖问题——历史 policy 的偏见会通过训练数据传递给新模型。

强化学习通过构建一个离线 simulator 来解决这个问题：让模型在 simulator 里自由探索，生成历史日志里没有出现过的候选广告路径，用生产环境的 pCTR/pCVR 排序模型评估这些候选的 eCPM，把评估结果作为奖励来更新模型参数。这样模型可以发现那些被历史系统遗漏的高价值广告。

**RL 在 GR 里有一个特有的困难：层级信用分配**

SID 有 L 层（比如 L=3），每层是一个独立的 token 决策。用户最终有没有点击广告（terminal reward），只在第三层决策完成后才知道。如果把这个结果奖励均匀归因给三层，会发生什么？

考虑一个具体的例子：模型生成了路径 [手机品类, 品牌A, 广告X]，用户没有点击。纯 terminal 奖励会同等地惩罚三层决策。但真实情况可能是：选"手机品类"是正确的（这个用户确实在看手机相关广告），只是"品牌 A"选错了（这个用户历史上从来没交互过品牌 A，偏好的是品牌 B）。均匀惩罚会错误地降低"选手机品类"这个正确决策的概率，让模型下次减少推荐手机广告——这显然是错的。

GPR 的 HEPO（Hierarchical Enhanced Policy Optimization）用一个轻量方案解决这个问题：从用户历史里统计每个 SID token 的"成功频次"——这个 token 在历史上出现在多少次最终被点击或转化的广告路径上。在 RL 训练时，对每一层的决策，计算当前选择的 token 的成功频次与同层所有合法候选的平均成功频次之差，把这个差值作为该层的"过程奖励"。

这样梯度信号精准：第一层的参数被正向强化（继续推荐手机品类），第二层的参数被 terminal 奖励惩罚（换个品牌），而不是两层都被错误地惩罚。实现成本很低：只需要维护一个"用户-token 成功频次"的稀疏计数表，不需要额外的模型或标注，直接从历史日志里统计。实验里，从 DPO 换到 HEPO，每个请求里 K 个候选中最高的价值得分从 0.6659 涨到 0.7619，提升 14.4%。

**三篇论文 RL 算法的差异**

GR4AD 的 RSPO 解决的是另一个问题：广告推荐优化的是一个排列列表，用户请求返回的是多个候选，关心的是这些候选的 eCPM 排序质量（NDCG），而不是单个候选的点击概率。RSPO 把 NDCG 的可微上界写成 preference optimization 的形式，同时用动态开关处理"参考模型过时"的问题——在大规模在线学习系统里，参考模型几天就会过时，过��的参考模型反而会产生错误的正则化约束，RSPO 用一个 KL 散度阈值检测这种情况并自动关闭参考约束。

UniVA 的 MCTS-PPO 关注的是探索覆盖：beam search 只探索高概率路径，那些语义得分普通但 eCPM 高的广告路径很容易被提前剪掉，永远得不到训练信号。Monte Carlo Tree Search 会主动往低概率分支探索，让这些被低估的路径也能参与训练。

HEPO 解决层级信用分配，RSPO 解决列表级目标对齐，MCTS-PPO 解决探索覆盖——三者是正交的，理论上可以组合，但组合后的训练稳定性需要实验验证。如果只能选一个优先实现，HEPO 的性价比最高：解决的问题最根本，实现成本最低。

## 第四个问题：线上怎么 serving

训练完成后，模型需要在 100ms 内对每个用户请求生成几十个候选广告。这个延迟预算比 LLM 推理严苛得多，需要专门的 serving 设计。

### Beam Search 的基本逻辑

GR 的 serving 核心是 beam search：维护一个"候选前缀集合"（beam），从第一层 SID token 开始逐层扩展。每一步，对 beam 里的每个前缀，展开它在下一层的所有合法后继，计算每个后继的得分，保留得分最高的 B 个（B 是 beam width）。走完 L 层，beam 里剩下的就是最终的候选广告集合。

### 第一件不能省的事：个性化 Trie

广告系统有大量的投放约束：这个广告只投特定年龄段、这个广告主今天预算跑完了、这个创意审核未通过……如果 beam search 在全部广告的 SID 空间里展开，很多 beam 路径走到底会发现对应的广告根本不能投放给当前用户，这些计算就全部浪费了。

UniVA 的实验数字：没有约束过滤时，beam width=300 的 300 条路径里，只有 48 条（16%）是真正可以投放的合法广告。

解决方案是个性化 Trie：在每个请求到来时，用当前用户的所有约束条件裁剪出一棵只包含合法候选的前缀树，beam search 只在这棵树的合法节点上展开。300 条 beam 全部变成有效候选，相当于在不增加任何计算开销的情况下，把有效召回扩大了 6 倍。

### 第二件不能省的事：在 Beam 评分里直接融合价值信号

如果 beam search 只看生成概率（模型认为这个 SID 有多大概率是用户想要的），那些语义得分普通但 eCPM 高的广告路径会在第一层就被剪掉，后续所有阶段都找不回来。

正确的做法是：在 beam 每一步的扩展评分里，把生成概率和价值估算加权融合，让高价值路径在 beam 中获得更宽的探索空间。GPR 和 UniVA 独立实现了同样的设计，且都有单独的消融实验证明其有效性。这是 serving 层"把价值当一等公民"的体现，和 SID tokenization 层"最后一层用确定性映射"是同一个设计哲学在不同位置的应用。

### 效率优化：LazyAR

GR4AD 发现了一个 beam search 计算量分布的不对称性：SID 第一层的 token 预测最难（模型不确定性最高），但这时候 beam width=1，计算量最小；SID 后几层预测相对容易，但 beam 已经扩展开，计算量最大。

标准自回归要求每生成一个 token，就把这个 token 的嵌入送回第一层，走完所有 transformer 层，再预测下一个 token。GR4AD 发现，decoder 的前 K=2L/3 层对"上一个 token 是什么"的依赖实际上很弱——这几层主要在做用户历史的深度理解，而不是在利用上一个生成 token 的信息。因此可以把这 K 层的计算提前做好，在所有 beam 之间共享，只有后 L/3 层需要真正串行地依赖上一个 token。

这个优化让 QPS 翻倍，而模型性能损失只有 -0.15% 收入，几乎无损。实现上也不需要改变模型结构或增加参数，只是改变了计算的执行顺序。

其他值得实施的工程优化：递增 beam schedule（第一层用窄 beam，越往后越宽，减少中间层的无效计算）；beam-shared KV cache（beam search 里共同前缀的 KV 只计算一次）；峰期/非峰期动态调整 beam width（利用服务器空闲算力）。这几个优化叠加后，GR4AD 实现了 <100ms 时延、500+ QPS/L20。

## 设计原则的提炼

把四个问题的分析归纳起来，广告 GR 系统设计有几条贯穿始终的原则。

商业价值必须从 tokenization 阶段就开始渗透，而不是在末端打补丁。SID 最后一层用确定性映射编码业务属性，让 token 空间本身具备商业区分力；beam search 里直接融合价值评分，而不是生成完再挂排序模块；RL 训练时用价值加权的过程奖励，而不是只在末端给 terminal 奖励。这三处的逻辑是一贯的：越晚注入的价值信号，能修正的错误越少。

广告输入的异构性必须在架构上正视，不能用均一参数混合处理。Token-Aware FFN/LN 贡献了所有组件里最大的单组件增益，说明这个问题是真实的性能瓶颈。工程上的修复成本低（改共享参数为分组参数），没有理由不做。

RL 探索是必要的，但 simulator 质量是核心风险。三篇论文的 RL 训练都依赖离线 simulator，且没有深入讨论 simulator 与真实竞价环境的偏差。广告的 eCPM 受实时竞价影响，历史平均 eCPM 可能系统性地低估高竞争时段的真实价值。这是当前广告 GR 方向最值得深入研究的开放问题。
