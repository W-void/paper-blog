# 持续预训练（CPT）完整指南


## 一、什么是持续预训练（CPT）

### 大模型训练的完整链路

大模型从零到可用，经历四个阶段：

**预训练（PT）→ 持续预训练（CPT）→ 指令微调（SFT）→ 对齐（RLHF）**

这四个阶段各自解决不同的问题，作用在不同的层次上。

**预训练（PT）** 是从零开始，用海量通用语料（几万亿 token）训练一个基座模型。模型在这个阶段学习语言的基本规律、世界的通用知识。成本极高，动辄几百万美元，通常只有大型机构才会做。

**持续预训练（CPT）** 是在已有基座模型上，继续用新数据做预训练。起点不同，但参数更新范围和 PT 一样——默认训练全部参数。目标是改变模型的知识储备，注入新的领域知识或更新已有知识。

**指令微调（SFT）** 是在 CPT 之后，用有标注的指令数据训练模型，让它学会"按照人类期望的方式回答问题"。目标不是注入知识，而是改变行为方式——让模型从"续写文本"变成"回答问题"。数据量通常只需要几千到几十万条。

**对齐（RLHF）** 是用人类反馈的强化学习，进一步让模型的输出符合人类价值观和偏好。这个阶段解决的是"模型会回答，但回答得不够好、不够安全"的问题。

### 四个阶段的核心区别

| 维度 | PT | CPT | SFT | RLHF |
|---|---|---|---|---|
| **起点** | 随机初始化 | 已有基座模型 | CPT 后的模型 | SFT 后的模型 |
| **目标** | 学习语言和通用知识 | 注入领域知识 / 更新知识 | 改变行为方式 | 对齐人类偏好 |
| **数据类型** | 无标注通用文本 | 无标注领域文本 | 有标注指令对 | 人类偏好标注 |
| **数据规模** | 万亿 token | 百亿～千亿 token | 千～百万条 | 万～十万条 |
| **参数更新** | 全参数 | 全参数 | 全参数或 LoRA | 部分参数 |
| **成本** | 极高 | 高 | 中 | 中 |

### CPT 和 LoRA 的区别

LoRA 经常被误用来做知识注入，但它本质上不适合这个任务。LoRA 冻结原始参数，只在旁边插入少量可训练的低秩矩阵，参数量只有原模型的 0.1%～1%。这种设计适合改变行为方式（SFT 阶段），但低秩矩阵的表达能力不足以承载大量新知识。如果你的目标是让模型真正掌握一个新领域，需要至少做部分层的全参数 CPT。

### CPT 和 CoT 的区别

CoT（Chain-of-Thought，思维链）是一种指导思想：复杂问题应该被显式拆解成中间步骤，而不是直接跳到结论。这个思想可以体现在任何阶段——推理阶段（提示词技巧）、训练数据（带推理链的样本格式）、模型架构（o1/R1 的思考建模）。

CPT 和 CoT 的本质区别是：**CPT 决定模型知道什么，CoT 决定模型怎么用它知道的东西。** 两者不是替代关系，可以叠加使用——CPT 注入领域知识，CoT 激活推理能力。

## 二、为什么需要 CPT

有三类典型需求：

**领域适配**：通用大模型不懂医疗、法律、金融、代码等专业知识，需要注入领域数据。LoRA 通常不够用，因为低秩矩阵无法承载大量新知识。

**知识更新**：模型训练数据有截止日期，新发生的事情它不知道，需要持续注入新知识。

**语言和能力扩展**：比如增强中文能力、增强数学推理能力，需要针对性地补充对应数据。

## 三、CPT 完整流程全景

一个完整的 CPT 项目本质上回答三个问题：**用什么数据、怎么训、训多少**。

```
原始语料池
    │
    ├──────────────────────────────┐
    │                              │
    ▼                              ▼
【筛选流水线】（内部串行）     【合成流水线】（独立并行）
    │                              │
    ├─ Step1: 规则过滤             ├─ 练习题合成
    ├─ Step2: fasttext 召回        └─ 知识改写合成
    ├─ Step3: 模型质量打分
    └─ Step4: 去重
    │
    ▼
高质量真实数据 ──── 按比例混合 ────▶ 最终训练数据集
                                          │
                                          ▼
                                    【训练配置】
                                    模型选择（Dense/MoE）
                                    优化器（Muon/AdamW）
                                    学习率（WSD 调度）
                                          │
                                          ▼
                              全程由 Scaling Laws 指导规模决策
                                          │
                                          ▼
                                  领域增强后的基座模型
```

筛选和合成是并行的，筛选内部必须串行（每步依赖上步输出），合成内部各方法可选。

### 3.1 数据工程

**数据质量比数据数量重要得多**，用 1T 高质量 token 训出来的模型，往往比用 10T 低质量 token 训出来的更好。FineWeb 的实验直接证明了这一点：FineWeb-Edu 只有 FineWeb 1/10 的数据量，但在多项 benchmark 上全面超越完整 FineWeb，也超越了 Dolma、RedPajama 等同期数据集。

#### 筛选方法对比

| 方法 | 解决的问题 | 计算成本 | 效果上限 | 适合场景 |
|---|---|---|---|---|
| 规则过滤 | 去掉明显垃圾 | 极低 | 低 | 第一道门槛，任意规模 |
| fasttext 分类器 | 领域召回 / 粗筛 | 低 | 中 | TB 级以上数据粗筛 |
| 模型质量打分 | 语义层面质量识别 | 高 | 高 | 百 GB～TB 级精筛 |
| 多轮迭代（FineWeb） | 确定最优筛选策略 | 极高 | 最高 | 研发阶段，结果可复用 |

这四种方法不是互相替代，而是流水线里的不同位置。规则过滤在最前面粗筛，fasttext 做领域召回，模型打分做精筛，多轮迭代是研发阶段用来确定前三步最优参数的——一旦规则确定，后续直接复用，不需要每次重跑。

**fasttext 领域召回的工程细节**（来自 DeepSeekMath，arXiv:2402.03300）：用少量高质量种子文档训练一个 fastText 二分类器，在整个 Common Crawl 上跑推理，**召回优先**（高 recall），宁可多捞一些噪声，也不漏掉好数据，再用重模型做精筛。为什么用 fasttext 而不是大模型？对 TB 级数据跑推理，fasttext 速度是神经网络模型的几百倍，性价比不可替代。

**FineWeb 数据流程的核心方法论**（HuggingFace blogpost-fineweb-v1）：多轮实验找到最优筛选策略，用 BERT 系模型对每条数据打教育价值质量分，筛出高质量子集。一旦规则确定，后续直接复用。

**MiniCPM4 的 UltraClean 流水线**（arXiv:2506.07900）把数据策略选择本身也自动化了：ModelTunnel v2 用小模型在不同数据配比策略下跑短训练，自动找到最优的数据混合比例，再放大到全量训练。8B 模型仅用 8T token 达到业界 SOTA，是数据质量换数据数量的最新工程验证。

去重是成本最低但收益最高的操作，MinHash 去重计算成本极低，没有理由跳过。互联网数据里大量近似重复内容不去重会导致模型过拟合，泛化能力下降。

#### 合成方法对比

| 方法 | 解决的问题 | ��算成本 | 数据增益 | 适合场景 |
|---|---|---|---|---|
| 练习题合成 | 推理能力弱、知识只会背不会用 | 高 | 质变（新增推理链） | 知识密集型领域 |
| 知识改写合成 | 数据多样性不足、泛化能力差 | 中 | 量变（多种表达） | 通用能力提升 |

练习题合成是"生产数据的方式"，CoT 是"数据的格式"。练习题合成生成的数据可以是普通问答格式，也可以是 CoT 格式（带完整推理链）。当合成数据带了推理链，练习题合成和 CoT 训练数据就完全重叠了。

**练习题合成的三条技术路线：**

第一条（arXiv:2406.00179）：直接让 LLM 读完整书籍（百万 token 上下文）生成 QA 对，评估用成对比较（Bradley-Terry 排名）代替绝对评分，结果更稳定。

第二条，**CLIPPER**（arXiv:2502.14854）：先把书籍压缩成章节摘要和提纲，再从压缩表示生成带 CoT 推理链的复杂 claims——压缩作为中间步骤，给了模型一个更"可操作"的输入，避免直接处理超长文本的质量问题。微调后的 sub-10B 模型在 NoCha 数据集上从 28% 提升到 76%，达到 SOTA。

第三条，**EntiGraph**（arXiv:2409.07431）：从领域文档里提取关键实体，随机采样实体对，让 LLM 生成描述这对实体之间关系的文本，用这批合成语料做 CPT。有两个重要发现：一是合成 CPT 之后，模型在推理时**不需要访问原始文档**就能回答领域问题，相当于把知识真正内化进了权重；二是**合成 CPT 和 RAG 是互补的**——合成 CPT 做完后再加 RAG，效果比单独用 RAG 更好，两者叠加是目前领域知识注入的最优实践。

**知识改写合成，MGA**（arXiv:2502.04235）：把已有语料改写成不同体裁（新闻/教程/故事）× 不同受众（专家/学生/大众）的多种版本，解决同一知识只以单一风格出现导致的泛化能力不足问题。基于此生成了 770B token 的 MGACorpus，已开源。在 13B 规模测试中效果超过简单重复和上采样策略。

合成数据占比超过 30%～40% 后，模型容易出现"合成腔"——输出风格变得模板化，缺乏真实文本的自然多样性。

#### 数据配比

领域数据和通用数据的混合比例是关键决策。配比不当会导致两种问题：领域数据比例太高，模型遗忘通用能力（灾难性遗忘）；比例太低，领域能力提升不明显。通常做法是先用 Scaling Laws 在小规模实验上找到最优配比，再放大到全量训练。

#### 常见踩坑

**坑一：跳过去重。** 去重是成本最低但收益最高的操作，却经常被忽视。MinHash 去重没有理由跳过。

**坑二：合成数据比例过高。** 合成数据占比超过 30%～40% 之后，模型容易出现"合成腔"——输出风格变得模板化、过于整齐，缺乏真实文本的自然多样性。

**坑三：筛选太激进。** 过度筛选会导致数据多样性不足，模型见过的内容太单一。一般建议筛选后保留原始数据的 20%～40%，而不是 5% 以下。

### 3.2 训练配置

#### 模型选择：Dense vs MoE

Dense 模型（LLaMA、Qwen）所有参数每次都参与计算，结构简单，CPT 流程成熟。

MoE 模型（DeepSeek、Kimi-K2）每次只激活部分专家参数，同等计算量下参数总量更大，能力上限更高。但 CPT 在 MoE 上有额外挑战：新数据分布会打破专家分工平衡，导致部分专家被过度更新，其他专家几乎不更新。解法是在 CPT 阶段对路由机制加额外的负载均衡损失，同时降低路由机制的学习率。

如果不想从头训 MoE，另一条路是从已有 Dense 模型出发做转换：LLaMA-MoE（arXiv:2406.16554）把 LLaMA-2 7B 的 FFN 层拆分成多个专家，用 200B token 做 CPT 完成转换，得到的 LLaMA-MoE-3.5B（激活参数量）在同激活量级的对比中显著领先 Dense 模型。


#### 大模型压缩：剪枝与蒸馏

如果目标是把大模型的能力搬进小模型（而非注入新知识），**剪枝 + 蒸馏**是比重训更高效的路线。英伟达的 Minitron 方案（arXiv:2408.11796）对 Llama 3.1 8B 和 Mistral NeMo 12B 做压缩：先做深度剪枝（删整层）或联合宽度剪枝（同时压缩 hidden size、attention head 数、MLP 维度），再用 teacher 做知识蒸馏恢复精度。一个实战技巧：若没有原始训练数据，先对 teacher 在蒸馏数据集上轻微 fine-tune 再蒸馏，效果显著好于直接蒸馏。得到的 Mistral-NeMo-Minitron-8B 在同量级开源模型中达到 SOTA。

📄 英伟达 NeMo 博客：https://developer.nvidia.com/blog/llm-model-pruning-and-knowledge-distillation-with-nvidia-nemo-framework/
📄 arXiv:2408.11796

#### 优化器：Muon vs AdamW

AdamW 是目前最主流的选择，稳定可靠，大多数 CPT 工作的默认配置。

Muon 是 2024 年底出现的新优化器，核心改进是对梯度矩阵做 **Nesterov 动量 + Newton-Schulz 正交化**，让每次参数更新都走"最陡的下坡方向"而不是沿坐标轴方向，收敛更快、效果更好。工程实践中，Embedding 层和 output head 仍用 AdamW，只对中间 MLP 和 attention 层改用 Muon。Kimi-K2 技术报告里有详细的 MoE 大规模验证。

📄 Muon 原始博客：https://kellerjordan.github.io/posts/muon/
📄 Kimi-K2 技术报告：https://github.com/MoonshotAI/Kimi-K2/blob/main/tech_report.pdf

#### 学习率：WSD 调度

传统 Cosine Decay 要求提前确定总步数，不适合需要灵活调整的 CPT 场景。

WSD（Warmup-Stable-Decay）把学习率分三段：Warmup 快速升温 → Stable 长期保持高学习率 → Decay 训练结束前快速下降。关键洞察是 Stable 阶段可以无限延长，随时插入新数据继续训练，只有决定"这个阶段结束"时才触发 Decay。

另一个重要发现：**Decay 阶段的数据质量比 Stable 阶段更重要**。Decay 阶段学习率快速下降，参数变化会"固化"，高质量数据的效果被放大，低质量数据的负面影响也被放大。工程实践中通常在 Decay 阶段专门使用筛选出的最高质量数据。

WSD 还带来一个工程红利：在 Stable 阶段保存 checkpoint，之后针对不同领域做 CPT 都从这个 checkpoint 出发，不需要每次从头训练。


#### 训练效率优化：modded-nanogpt

以"每次提交都要比上一版更快达到 loss 目标"为原则的工程极限挑战项目，汇集了 Muon 优化器实现、FlexAttention、RoPE 等现代架构组件和极致的 CUDA 内核优化技巧，是验证训练效率技巧、测量实际加速效果的权威工程参考。

### 3.3 规模决策：Scaling Laws

在正式开始大规模 CPT 之前，需要回答：给定计算预算，应该用多大的模型、训多少数据？

**OpenAI Scaling Laws**（arXiv:2001.08361）奠定了基本规律：模型 loss 和参数量 N、数据量 D、计算量 C 之间存在稳定的幂律关系，可以跨 7 个数量级外推，架构细节影响很小。

**Chinchilla**（arXiv:2203.15556）给出了最重要的实践结论：最优配置下，参数量和训练 token 数应该等比例增长，大约每个参数对应 20 个 token（70B 模型配 1.4T token）。这意味着很多早期大模型都是"参数过多、数据不足"的次优配置——Chinchilla 70B 用 4 倍数据，超越了当时所有 175B～530B 的模型。

**StepFun** 把 Scaling Laws 推进到了工程直接可用的精度：Part I（arXiv:2503.04715）用约 100 万 H800 GPU 小时训练 3700+ 个 LLM，推导出最优学习率和批大小随 N、D 变化的幂律，且统一覆盖 Dense 和 MoE 架构，预测误差仅 0.094%。Part II Farseer（arXiv:2506.10972）构建了更精准的 loss 曲面 L(N, D)，外推误差比 Chinchilla 降低 433%。

**在 CPT 中的实际用法**：先��小规模（1B 模型 + 10B token）上跑一批对照实验，测试不同数据配比、不同学习率的效果，用幂律外推预测大规模训练结果，再决定是否投入全量资源。这样可以把试错成本压缩到总成本的 5%～10%。

## 四、成本-收益权衡

### 成本的量级

用 A100 80G 训一个 7B 模型，在 100B token 上做 CPT，大约需要 200～400 张 A100 跑一周，折算云厂商价格大概是几十万到百万人民币。这是"从头做一个完整 CPT"的成本，实际工程中有很多方式可以压缩。

### 四个控制成本的手段

**小规模预实验优先**：在投入全量资源之前，先用 1B 以下小模型 + 少量数据跑对照实验，用 Scaling Laws 外推大规模效果。这是最重要的成本控制手段，把试错成本压缩到总成本的 5%～10%。

**WSD checkpoint 复用**：在 Stable 阶段保存 checkpoint，之后每次针对新领域做 CPT 都从这个 checkpoint 出发，不需要每次从头训。

**模型规模匹配需求**：不是所有场景都需要 70B 模型，7B 甚至 3B 做 CPT 往往已经够用，成本差距是数量级的。

**数据质量换数据数量**：FineWeb-Edu 的实验证明，用 1/10 的高质量数据效果可以超过 10 倍的低质量数据。在数据工程上多花时间，可以显著减少训练所需 token 数。

### 什么时候值得做 CPT

```
模型根本不懂你的业务领域？
    │
    ├─ 是 → 需要 CPT
    │         │
    │         ├─ 领域数据充足（>100B token）
    │         │       └─ 完整筛选流水线 + 合成数据补充
    │         │
    │         └─ 领域数据稀缺（<10B token）
    │                 └─ 合成数据为主（练习题合成优先）
    │                    真实数据筛选后混入
    │                    合成 CPT 完成后叠加 RAG
    │
    └─ 否 → 推理链路复杂？
                │
                ├─ 是 → CoT 提示词就够了，不需要 CPT
                │
                └─ 否 → SFT/LoRA 调整行为方式即可
```

### 三个优先级建议

如果资源有限，按这个顺序投入精力：

**数据工程 > 学习率调度 > 优化器选择**

数据质量是天花板，再好的训练技巧也救不了烂数据。WSD 是 CPT 场景特有的关键技巧，值得优先掌握。Muon 是锦上添花，在数据和调度都做好之后再考虑。

真正让很多团队望而却步的不是成本本身，而是**成本和收益的不确定性**——不知道 CPT 之后效果能提升多少，不敢投入。这也是为什么 Scaling Laws 和小规模预实验这套方法论如此重要：它的核心价值就是在大规模投入之前，给你一个相对可靠的效果预测，把决策从"赌博"变成"有依据的投资"。
