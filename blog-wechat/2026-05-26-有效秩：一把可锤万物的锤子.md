# 有效秩锤万物：从腾讯的3篇论文中学习

> 从推荐系统到大语言模型，一个来自信号处理的古老概念，正在成为深度学习领域最重要的诊断工具之一。

---

你有没有遇到过这种情况：

推荐模型的 embedding 维度从 64 扩大到 512，参数量增加了 64 倍，但线上效果反而下降了？

LoRA 微调分配了 rank-64 的子空间，但训练结束后发现实际上只用了其中十几个方向，其余的全是浪费？

Transformer 堆了几十层，token 的表示越来越相似，模型越来越分不清不同的输入？

这三个问题，表面上看毫不相关，背后却是同一个诊断——**有效秩太低**。

---

## 什么是有效秩？

2007 年，信号处理领域的两位研究者 Roy 和 Vetterli 提出了这个概念。

直觉解释起来其实很简单：

想象一个 512 座的音乐厅，但实际上只有 50 把椅子有人坐，其余 462 把空着。名义上是 512 座，实际容量只有 50。

矩阵也是一样。一个 512 维的 embedding 矩阵，名义上有 512 个维度，但实际上可能只有 50 个维度"有内容"，其余的都是冗余。

有效秩就是那个"实际上有多少把椅子有人坐"的数字。

具体计算方式：把矩阵做奇异值分解，得到一组反映各个方向"重要程度"的奇异值。把这些奇异值归一化成概率分布，然后计算这个分布的香农熵，再取指数，就得到了有效秩。

直觉上，如果所有能量集中在一两个方向（音乐厅里只有两把椅子有人），熵很低，有效秩接近 1。如果能量均匀分布在所有方向（每把椅子都坐了人），熵最大，有效秩等于矩阵的真实维度。

有效秩是一把**连续的尺子**，能区分"名义上满秩但实际低秩"的矩阵——这正是它比普通秩更有用的地方。

---

## 你的模型，可能正在悄悄"坍塌"

有了这把尺子，研究者们开始测量各种模型的表示空间——然后发现了一个令人不安的普遍现象：

**大多数深度模型的有效秩，都远低于它们的名义维度。**

这个现象有一个名字，叫**秩坍塌（Rank Collapse）**。

### 为什么纯 Attention 必然坍塌？

从 Transformer 的结构出发，自注意力的本质是：把当前层的输入矩阵，先经过注意力加权求和，再乘以一个值矩阵。

这里有一个关键的数学事实：**矩阵乘法不增加秩**。

每经过一层，秩只会降低或持平，永远不会增加。

但问题比这更严重。注意力矩阵的每一行是一个概率分布（softmax 归一化），这使它成为一个"随机矩阵"。随机矩阵有一个特殊性质：反复用它去"混合" token 的表示，效果是不断放大所有 token 的平均值，同时以指数速率压缩 token 之间的差异。

Dong 等人（ICML 2021）给出了精确的定量结果：对于纯 Attention 网络（没有残差连接、没有 FFN），经过足够多层之后，所有 token 的表示会退化为同一个向量——秩坍塌到 1，模型彻底失去区分不同输入的能力。衰减速率是**双指数**的，快到令人震惊。

### Transformer 的三道防线

真实的 Transformer 当然不会退化得这么极端，因为它有三个对抗秩坍塌的结构性机制：

**残差连接**：每层的输出是"注意力结果"加上"原始输入"。加法操作从代数上保证了：即使注意力把所有信息压缩到一个方向，原始输入仍然完整地传递到下一层。Dong 等人证明，加入残差连接后，秩的衰减速率从双指数降为多项式级——仍然在衰减，但慢得多。

**FFN 的非线性激活**：FFN 中的 ReLU 或 GeLU 对不同 token 施加不同的"开关"，等价于在每一层重新选择激活的子空间，让后续的线性变换有机会在新的方向上重建秩。这是 FFN 能够"恢复"被注意力压缩的秩的根本原因。

**Attention Mask**：因果语言模型的下三角掩码打破了注意力矩阵的对称性，消除了"均匀分量的主导地位"，减缓秩坍塌。

这三道防线共同作用，使得真实 Transformer 的有效秩不会归零。但"不会归零"不等于"没有问题"——在实际训练好的模型里，有效秩仍然远低于维度上限，大量参数在做重复的事情。

更麻烦的是，秩坍塌不只发生在注意力层。推荐系统的 embedding 矩阵会坍塌，特征交叉操作会加剧坍塌，多任务学习的梯度干扰会引发坍塌，静态特征和序列特征混合建模会传播坍塌。这就是有效秩在深度学习时代变得重要的原因：它是诊断这类问题的**定量工具**。

---

## 有效秩越高越好吗？

理解了定义，一个自然的问题随之而来：有效秩越高越好吗？

表面上看，答案应该是肯定的。但有一个反例会让你停下来：随机矩阵的有效秩是所有矩阵里最高的——它的奇异值分布最均匀，熵最大。而随机矩阵显然是最没用的矩阵。

更反直觉的是，NeurIPS 2024 有一篇论文（Diff-eRank）发现：**训练得越好的大语言模型，隐层表示的有效秩反而越低。** 这是因为训练的本质是"去噪"——把随机初始化时均匀分布在所有维度的噪声压缩掉，让表示变得有结构。有效秩下降，说明模型成功地把冗余信息清除了。

那推荐系统里为什么又要拼命追求高有效秩？

**这两者并不矛盾，因为它们比较的基准完全不同。**

Diff-eRank 比较的是"同一个模型，训练前 vs 训练后"。训练前是随机噪声，训练后是有意义的结构，有效秩从高到低，是去噪的过程，是好事。

推荐系统里比较的是"两个都已经训练好的模型，架构 A vs 架构 B"。两个模型都已经学到了有意义的结构，此时有效秩更高的那个，说明它的表示空间被更充分地利用了——512 个维度里有 200 个在工作，而不是只有 20 个在工作，其余 492 个维度是冗余的。这不是噪声多，而是**容量被浪费了**。

所以，有效秩研究的真正问题不是"高还是低"，而是：**在模型已经学到有意义表示的前提下，它有没有充分利用分配给它的参数空间？**

理解了这个区分，才能正确解读后面所有的工作。

## 一、腾讯的一鱼N吃：用有效秩解剖 Mixer 架构

最近字节跳动的 RankMixer、OneTrans 等工作带火了精排模型的 scaling 化——把推荐系统的精排模型往 Transformer/Mixer 方向做大，已经成为工业界的主流方向。

但模型做大之后，一个问题随之而来：参数量上去了，效果真的等比例提升了吗？

腾讯团队连续发出三篇论文，从三个不同维度发起反击。

### 1.1 RankMixer 的隐藏病症

字节跳动在 2025 年提出了 RankMixer，用"块转置混合"替代标准自注意力，在工业推荐系统中取得了不错的效果。但腾讯团队用有效秩做了一次深度解剖，发现了一个隐藏的病理：**阻尼振荡**。

在 RankMixer 的每一层里，有效秩的变化轨迹呈现出一种奇特的模式：token mixing 之后，有效秩小幅上升；P-FFN 之后，有效秩大幅下降。一升一降，净效果是负的。模型越深，表示空间反而越"萎缩"。

原因在于 P-FFN 的结构：它是先升维再降维的瓶颈设计，降维那一步是纯线性矩阵乘法。纯线性变换只降秩不升秩。加上 GELU 的非线性强度不足以抵消降维的压缩效果，P-FFN 整体上成了秩的净消耗者。

**RankElastor**（KDD 2026）针对这两个问题各开了一剂药：

![](https://files.mdnice.com/user/83179/0ec31ba0-3be9-4aa2-a635-706f6d34ac42.png)

- 把固定的块转置置换换成**可学习的全参数化混合矩阵**，让模型自适应地决定哪些 token 之间交换信息，覆盖更多的表示方向。
- 把 GELU 换成 **GLU（门控线性单元）**。GLU 的逐元素乘法引入了跨维度的非线性交互，既能过滤冗余信息，又不会像纯线性降维那样系统性地压缩秩。

设计原则被概括为四个字：**Expand More, Shrink Less**。这四个字其实整个贯穿了腾讯的这几篇论文。

论文用四个定理完整证明了这条因果链：块转置混合的有效秩提升有上界、GELU-FFN 在低秩输入下会进一步收缩有效秩、可学习全混合的表达能力严格更强、GLU 的乘法结构能主动提升有效秩而不是压缩它。

AUC 因果证据：两个模块有协同效应——GLU 的有效秩保持能力，需要全混合先把有效秩扩张到足够高的水平才能充分发挥。最终在 Criteo 和 Avazu 两个公开数据集上，AUC 显著超过原始 RankMixer，且随着模型规模增大，优势进一步扩大——说明修复 collapse 对模型的 scaling 行为有根本性影响。

### 1.2 从源头提升"原材料"质量

RankElastor 解决的是架构内部的 collapse。但腾讯团队意识到，即使架构设计完美，如果输入特征本身的有效秩就很低，collapse 仍然会发生。

**RankUp**的切入点更上游：不改架构，改"原材料"。

![](https://files.mdnice.com/user/83179/00085412-9147-427f-a83d-47f3d2bb320f.png)

传统推荐系统的特征处理方式，是把相关特征分组放在一起，然后共享同一套 embedding。这就像把所有食材扔进同一口大锅——高度相关的特征互相稀释，embedding 空间的多样性很低。

RankUp 提出了五个互补机制，全链路提升输入端的有效秩：

**随机置换分割**：打破语义分组，把特征随机打散重新分组。听起来反直觉，但实验证明，随机分组后 token 的有效秩显著提升——不相关的特征放在一起，反而迫使模型学习更多样化的表示。

**多嵌入范式**：为每个特征学习多套独立 embedding，从多个角度"拍照"，捕捉不同层面的语义信息。

**全局 token**：引入一个可学习的全局 token，作为整个序列的"综合营养素"，提供全局上下文信息。

**预训练 embedding 交叉集成**：引入外部预训练 embedding（如商品文本 embedding），与模型内部 embedding 交叉融合，引入外部先验知识。

**任务特定 token 解耦**：在多任务学习中，为每个任务（32 个广告任务）分配独立的 token，避免不同任务的梯度互相干扰。

值得注意的是，五个机制都提升了 AUC，但与有效秩的关系并不完全一致。前三个机制直接作用于输入端的有效秩，走的是"提升有效秩→提升 AUC"的路径；任务 token 和全局 token 的贡献，则更多体现在"判别性"和"深层稳定性"上，有效秩只是其中一个中间变量。

这说明，有效秩是必要条件，但不是充分条件——输入端的表示多样性需要同时在"维度利用率"和"任务判别性"两个维度上都达标，模型才能充分发挥潜力。

五个机制叠加后，在微信视频号、公众号、朋友圈三个广告场景全量上线，GMV 分别提升 3.41%、4.81%、2.12%。对于新广告冷启动场景，公众号 GMV 提升高达 9.67%。

### 1.3 统一建模带来的新型 Collapse

当推荐系统开始把多字段静态特征（用户画像、商品属性等）和序列行为特征统一放进同一个 Transformer 里建模时，一种新型的 collapse 出现了。

腾讯团队把这个现象命名为 **SCP（Sequential Collapse Propagation，序列坍塌传播）**：静态特征的有效秩天然很低（用户画像字段高度相关），当它们和序列特征一起参与注意力计算时，低秩的静态特征会通过注意力机制，把序列特征的有效秩也拉低——就像一个沉默的班级合并进来，把整个教室的"表达多样性"都拉低了。

**TokenFormer**（2025）提出了两个针对性的解法：


![](https://files.mdnice.com/user/83179/3c5af8cb-7427-4edb-93a8-2884fe236f2b.png)


**BFTS（底层全注意力-顶层滑动窗口）**：在浅层，让静态特征和序列特征充分交互，完成信息整合；在深层，切换到滑动窗口注意力，让序列特征只关注局部邻居，隔离静态特征的"污染"。

**NLIR（非线性信息保留）**：在注意力输出上加一个乘法门控，让模型自己决定从交互中保留什么、丢弃什么，而不是被动地接受所有信息。

这个设计揭示了三篇论文中最重要的洞察之一：**有效秩和判别性是两个独立的维度，缺一不可。**

朴素统一建模的失败，不是因为有效秩太低（它的判别性其实更高），而是因为 SCP 把有效秩压低到了一个临界点以下。BFTS + NLIR 的价值，在于同时修复了这两个维度。

TokenFormer 上线后，GMV 提升 4.03%，同时 serving 吞吐量从 126 QPS 提升到 695 QPS，提升了 5.5 倍——因为滑动窗口注意力的计算复杂度远低于全注意力。效果和效率，同时提升。

## 二、这把锤子，早就有了

前面腾讯三篇论文看起来是 2025 年的新工作，但它们背后的诊断框架——**用有效秩发现 collapse，用架构改进修复 collapse**——其实在推荐系统领域早就建立起来了。

腾讯和清华大学的研究者们发现：把推荐模型的 embedding 维度从 64 扩大到 512，模型效果不升反降。

他们用有效秩做了一次"体检"。结果令人震惊：embedding 矩阵的有效秩远低于 embedding 维度。一个 512 维的 embedding 空间，实际上只用了不到 50 个维度，其余全是冗余。

这篇发表于 ICML 2024 的论文找到了一个出人意料的罪魁祸首：**特征交叉操作**。

![](https://files.mdnice.com/user/83179/f23bc483-1d1b-42ae-b67b-7502056d29d6.png)

推荐系统中，特征交叉是标配。DCN V2、AutoInt、xDeepFM……这些模型的核心都是让不同特征之间相互"交叉"，学习高阶组合信息。但论文从理论上证明了一个残酷的事实：**特征交叉操作会系统性地降低 embedding 的秩。**

原因就是矩阵乘法的基本性质：每一次特征交叉，本质上都是一次矩阵乘法，每乘一次，秩只会降低或持平，永远不会增加。堆叠越多的交叉层，embedding 的有效秩就越低，最终坍缩到一个极低维的子空间里。

解法是**多嵌入范式（Multi-Embedding）**：为每个特征学习多套独立的 embedding，让不同的副本在不同的子空间里各自发展，避免单一 embedding 被交叉操作反复压缩。

这篇论文确立了一个核心范式：**用有效秩诊断问题，用架构改进修复问题**。腾讯后来的三连击，不过是拿着同一把锤子，在 Mixer 这个新架构里找到了新的钉子。

## 三、长序列推荐：低秩是诅咒，也是礼物

在长序列推荐领域，有效秩的故事有一个有趣的转折：**低秩结构，从问题变成了解法**。

用户的行为序列，本质上是一个矩阵：行是时间步，列是 embedding 维度。研究者们发现，这个矩阵在实践中往往是低秩的——用户的兴趣虽然多样，但可以被少数几个"主题"概括。这个低秩性，不是缺陷，而是用户行为的内在��律。

**SOLAR**（快手，2025）是目前最直接利用这一规律的工作。

![](https://files.mdnice.com/user/83179/28031c84-f4aa-4b2d-a3bd-890386566ee1.png)

它的核心操作：对用户行为序列的 embedding 矩阵做截断 SVD，只保留最重要的少数几个方向，压缩掉噪声维度，把注意力计算的复杂度大幅降低。由于用户行为序列本身就是低秩的（实验显示保留约 27 个方向即可捕获全部信息），这个截断几乎是无损的——丢掉的都是噪声。

在快手线上部署，SOLAR 将 CPU 核心使用率降低了 52.38%，同时视频播放量提升 0.68%。

同期，阿里巴巴的 **LREA**（SIGIR 2025）从 DeepSeek MLA（多头潜在注意力）借鉴灵感，用两个可学习矩阵对序列长度维度做低秩压缩，训练完成后把解压矩阵预先吸收进序列表示缓存到 HBM，推理时只加载压缩后的序列，彻底消除在线计算开销。线上 A/B 测试 CTR 提升 5.88%，推理延迟仅增加 3ms。

## 四、大语言模型：有效秩的三种用法

有效秩在大语言模型领域的应用，覆盖了从训练效率到模型评估的多个层面。

### 4.1 微调参数怎么分配？让有效秩来决定

LoRA 是目前最流行的大模型微调方法：冻结预训练权重，只训练低秩的增量矩阵。但原始 LoRA 对所有层用同一个固定 rank，这显然是粗糙的——不同层的信息密度差异很大，凭什么用同样的 rank？

**AdaLoRA**（ICLR 2023）是第一个系统解决这个问题的工作。它根据每个奇异值三元组对训练损失的敏感度，动态地把不重要的奇异值剪枝至零，把 rank 预算集中分配给信息密度高的层。

**GeLoRA**（EMNLP 2025）从理论上证明了：LoRA 的 rank 不能低于该层表示的内在维度，否则必然有信息损失。它在微调过程中动态计算每层的内在维度，并据此分配 rank，把有效秩从诊断工具变成了**设计约束**。

**PoLAR**（NeurIPS 2025）发现了一个更隐蔽的问题：即使分配了足够的 rank，实际训练中稳定秩往往远低于分配值——子空间没有被充分利用，出现了"方向多样性崩溃"。PoLAR 通过保持方向矩阵的正交性来充分利用分配的子空间。

### 4.2 模型好不好？让有效秩来评估

传统的 LLM 评估依赖 benchmark——用标注数据测试模型的输出质量。但这有一个根本性的局限：需要大量标注数据，且对数据分布敏感。

**Diff-eRank**（NeurIPS 2024，上交大+清华）提出了一个完全不同的思路：用有效秩衡量模型的"去噪能力"。

核心直觉：LLM 训练本质上是一个去噪过程，模型通过训练消除表征空间中的冗余信息，让隐层表示变得更加结构化。训练前，表示是高度随机的，有效秩很高；训练后，有效秩下降。这个下降幅度，就是模型"去噪能力"的量化。

实验表明，这个指标与模型规模和下游任务性能的相关性，比交叉熵损失更稳定。更重要的是，它**不依赖任何标注数据**，可以在没有 benchmark 的情况下评估模型的表示质量。

对多模态模型，Diff-eRank 还可以用来评估模态对齐质量：比较图像表示和文本表示的有效秩匹配程度，匹配越好，说明两个模态的信息密度越接近，对齐越充分。

### 4.3 Attention 的谱分析：找到 Collapse 的根源

**Mind the Gap**（ICML 2025，牛津大学）用随机矩阵理论对 softmax 注意力做了一次深度解剖，发现了一个此前未被注意到的现象：**宽度 Rank Collapse**。

问题的根源在于 softmax 的行归一化：注意力矩阵必然有一个特征值为 1，而其他特征值随 token 数量增加集中在一个收缩区间内。这个"谱间隙"使得连续的矩阵乘法不断放大主导方向，导致不同 token 的表示被拉向同一个方向。

论文证明，随着 token 数量增加，稳定秩以平方根倒数的速率崩溃，梯度范数以指数速率增长。

解法出人意料地简单：**中心化注意力矩阵**，即减去均匀注意力分量。这个操作消除了谱间隙，从理论上保证了稳定秩不再崩溃。

## 五、防止秩坍塌：一张方法论地图

回顾全文提到的所有防御手段，它们背后有一个统一的逻辑起点：**矩阵乘法不增加秩**。

神经网络的前向传播本质上是一系列矩阵乘法的复合，每经过一次线性变换，秩只会减小或持平，永远不会增加。所有的防御手段，都是在对抗这个单调性。

**手段一：用加法对抗乘法的压秩效应**

乘法压秩，加法保秩。最直接的对策是在乘法路径旁边并联一条加法路径。

残差连接是这个思想最纯粹的实现：即使注意力层经过多层压缩后秩很低，加法把秩的下界兜住了。DIN 的"A + B + AB"结构同理：只有交互项的话，秩被两者的最小值限制；加上独立项之后，即使交互项秩很低，各自的信息仍然完整保留。

**手段二：用非线性打破线性压秩的单调性**

纯线性变换的复合，秩只能单调不增。非线性激活函数打破了这个单调性——ReLU 对不同 token 施加不同的"开关"，让后续的线性变换有机会在新的方向上重建秩。RankElastor 用 GLU 替换标准 FFN，正是因为 GLU 的逐元素乘法引入了更强的跨维度非线性交互，能主动提升有效秩，而不是像纯线性降维那样压缩它。

**手段三：限制单次乘法的压秩幅度**

既然每次乘法都可能压秩，那就控制每次压缩的程度。Attention Mask、TokenFormer 的滑动窗口注意力、NLIR 的乘法门控、Mind the Gap 的中心化注意力——都是从不同角度限制单次注意力操作的压秩幅度。

**手段四：显式建模低秩结构，把压秩变成可控的设计**

前三类都是被动防御。还有一类是主动承认低秩的存在，把它变成一个可以精确控制的设计参数。LREA 和 SOLAR 都属于这一类：既然数据本身是低秩的，就把低秩结构显式地学出来或者算出来，在已知的低秩子空间内做精确计算。DeepSeek MLA 同理——把低秩变成工程优势。

| 根本原因 | 对应手段 | 代表设计 |
|---------|---------|---------|
| 乘法压秩 | 并联加法路径 | 残差连接、DCN 的 A+B+AB |
| 线性复合单调压秩 | 引入非线性打破单调性 | FFN 激活函数、GLU（RankElastor） |
| 单次乘法压缩过度 | 限制每次压秩幅度 | Attention Mask、BFTS/NLIR（TokenFormer）、中心化注意力 |
| 低秩不可避免 | 显式建模，变被动为主动 | LREA、SOLAR、DeepSeek MLA |

这张表有一个值得注意的地方：前三类手段都是在"对抗"低秩，第四类手段是在"利用"低秩。两者并不矛盾——低秩是数据的客观属性，模型的表示空间应该尽量把这有限的秩用足、用好，既不浪费，也不退化。

## 尾声：一把古老的尺子，一个新的时代

Roy 和 Vetterli 在 2007 年提出有效秩时，大概没有想到这个概念会在十几年后的深度学习时代焕发出如此强大的生命力。

它的优雅在于：用一个数字，捕捉了矩阵"实际上有多少维度在工作"这个直觉。这个直觉，在信号处理里是有用的，在推荐系统里是有用的，在大语言模型里也是有用的。

这个概念沉寂了十几年，不是因为锤子不好用，而是因为钉子还不够多。直到深度学习的 scaling 时代到来，模型越堆越大，collapse 的问题越来越无法忽视，这把锤子才突然变得炙手可热。更重要的是，武器库里有了这把锤子，研究者才能在每一个新架构里系统性地找到新的钉子——从特征交叉到 Mixer，从 LoRA 到多模态对齐，��效秩的应用边界还在持续扩展。

当我们把越来越多的参数堆进模型，当我们把越来越长的序列喂给 Transformer，当我们把越来越多的模态融合进同一个架构——有效秩提醒我们：

**参数量不等于表达能力，维度不等于信息量，规模不等于质量。**

真正重要的，是那个被充分利用的子空间有多大。
