## 缺口：LastN 的三堵墙

推荐系统的用户历史建模，长期以来靠一个简单策略撑着：**LastN**——只保留最近 N 天的行为。这个策略的逻辑很直觉：越近的行为越相关，越远的行为越是噪声。

但当你把 N 推到 70 天以上，CTR 模型的 NE 增益就开始停滞了。CVR 模型稍好，能撑到 180 天，但也到头了。这不是数据不够，而是 LastN 本身撞上了三堵墙：

**第一堵墙：注意力稀释（Needle in the Haystack）。** Transformer 的注意力机制对所有位置做 pairwise 计算。当序列里 99% 的条目都和当前广告无关时，真正有用的那几条信号被淹没在噪声里——GPT-4 在长上下文里也有同样的问题，这不是模型能力的问题，是信息密度的问题。

**第二堵墙：系统效率。** 注意力的 O(n²) 复杂度让百万级序列在实时排序里根本跑不起来。即使用 FlashAttention 等高效变体，存储和计算仍然随数据量线性到平方增长。Meta 的广告系统每天处理数十亿请求，哪怕每个请求多 1ms 都是灾难。

**第三堵墙：灾难性遗忘（Catastrophic Forgetting）。** 推荐模型在滚动时间窗口上持续训练，梯度更新会逐渐覆盖旧的行为模式。Meta 的实测数据触目惊心：**在 30 天窗口上训练的模型，对 6 个月前行为模式的预测性能损失超过 50%**。季节性购物者、长购买周期用户——这些人的历史信号被模型系统性地遗忘了。

已有的工作（TWIN、PinnerFormer、DV365）都在尝试延长历史窗口，但它们要么假设 query 和 document 在同一 embedding 空间（限制了检索灵活性），要么没有解决遗忘问题（梯度仍然偏向近期数据）。

缺口很清晰：**如何在不线性扩大计算代价的前提下，把 365 天的用户历史真正用起来，同时对抗灾难性遗忘？**

## 增量：把历史当文档库，把广告请求当查询

Memento 的核心洞察是一句话的重新定义：**历史扩展本质上是一个信息检索问题。**

以前大家想的是"怎么让模型处理更长的序列"，Memento 说：不对，应该想"怎么从海量历史里检索出最相关的那一小部分"。

这个重新定义打开了一扇门：RAG（检索增强生成）在 LLM 领域已经证明，把外部知识库和模型推理解耦，是处理大规模外部知识的正确范式。Memento 把这个范式搬到了推荐系统——用户的全部历史行为是"文档库"，每个广告请求是"查询"，检索出来的相关历史片段是"增强上下文"。

这个增量让我们知道了什么以前不知道的：**RAG 范式不只适用于 LLM 的知识增强，同样适用于推荐系统的历史扩展——而且在 365 天历史上，RAG 风格的扩展在 CTR 和 CVR 上都能持续提升，而 LastN 线性扩展早已饱和。**

具体数字：RAG 风格扩展在 365 天历史上实现 0.25–0.30% NE 增益，而 LastN 在 CTR 模型 70 天、CVR 模型 180 天后就停止增益了。生产环境：Facebook Feed 和 Reels CTR +1%，CVR +1.2%。

## 核心机制：MMR 检索 + 双应用

### 系统架构

Memento 的架构分三层：

```
┌─────────────────────────────────────────────────────────────┐
│                    广告请求（Query）                          │
│  时间维度 + 用户群体 + 广告类目 + 兴趣主题 → 多维查询向量     │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                  Memento 检索层                               │
│                                                              │
│  用户历史 → 时间分块（7天一块）→ 嵌入向量 → VectorDP 索引    │
│                                                              │
│  MMR 评分：                                                  │
│  score(Di) = α·SimUU(Di,Q) + β·SimUA(Di,Q)                  │
│             - (1-α-β)·max SimUU(Di,Dj)                      │
│                         Dj∈已选集合                          │
│                                                              │
│  三个相似度：用户-用户 / 用户-广告 / 文档间多样性惩罚         │
└──────────┬───────────────────────────────────────┬──────────┘
           │                                       │
┌──────────▼──────────┐               ┌────────────▼──────────┐
│  Representation     │               │  Data Memento         │
│  Memento            │               │                       │
│  （推理时特征增强）  │               │  （训练时数据回放）    │
│                     │               │                       │
│  检索历史 embedding  │               │  检索历史训练样本      │
│  → Ember 架构融合   │               │  → 第二轮训练回放      │
│  → CTR/CVR 模型     │               │  → 对抗灾难性遗忘      │
└─────────────────────┘               └───────────────────────┘
```

### MMR：相关性与多样性的平衡

MMR（Maximal Marginal Relevance）是 1998 年 Carbonell & Goldstein 提出的经典算法，原本用于文档摘要的多样性重排序。Memento 把它改造成三项加权：

- **α·SimUU(Di, Q)**：用户历史片段和当前用户状态的相似度（用户侧相关性）
- **β·SimUA(Di, Q)**：用户历史片段和目标广告的相似度（广告侧相关性）
- **-(1-α-β)·max SimUU(Di, Dj)**：对已选集合中最相似文档的惩罚（多样性）

迭代地选择得分最高的文档加入已选集合，直到达到目标数量。

实验发现：α=0.7, β=0 时（纯用户侧相似度）在 50% 过滤率下效果最好；当过滤率更激进（25%）时，结合用户侧和广告侧相似度（α=0.05, β=0.8）能额外带来 0.06% NE 增益。β 过高（0.95）反而会损害多样性，效果下降。

### Representation Memento：推理时特征增强

**检索阶段**：用户历史被编码成每日 embedding（64–256 维，约 40 个来源），7 天一块做时间分块，再用 NormInt8 量化（比 FP16 节省约 50% 存储）。MMR 从 O(100K) 的序列里检索出 60 个最相关的 embedding，存储从 701K 降到 50K 浮点数/用户（14× 压缩）。

**Ember 架构**：检索到的历史 embedding 不是简单拼接，而是通过两种方式融合：

**Ember-Affine**：用历史上下文 c 对当前用户 embedding e(x) 做仿射调制：
```
e'(x; c) = γ(c) ⊙ e(x) + β(c)
```
一个小 MLP 从 c 生成每维度的缩放 γ 和偏移 β，初始化为恒等变换（γ=1, β=0），让模型学习何时偏离。计算代价 O(d)，避免了 attention 的 pairwise 开销。

**Ember-Quadratic**：在 LCE 压缩之前，用二次神经网络（QNN）对原始 embedding 做显式特征交叉：
```
Ψ(Xh) = Xh ⊙ ReLU(Wah·X) + Xh
```
这解决了 EFA 架构中"3800 个 embedding 槽被压缩到 64 个之后才做交叉"的信息损失问题。

两者叠加（Affine + Quadratic）在 CTR 上额外带来 0.03% NE 增益，同时保持 50K 存储/用户。

### Data Memento：训练时数据回放

**问题定位**：推荐模型在滚动窗口上训练，梯度偏向近期数据，旧的行为模式被覆盖。

**解法**：把历史训练样本（user, ad, label 三元组）也做 embedding，按小时分块，用 MMR 从 365 天历史里检索出最"被遗忘"的样本，在第二轮训练中回放。

**关键设计——参数重置**：第二轮训练前，重置模型的稀疏参数（embedding 表），用更大的学习率重新学习。这防止了模型通过大容量 embedding 表"死记硬背"回放样本，迫使稠密层学习可泛化的模式。

实验对比（CVR 模型，相对于 150+ 天训练的生产基线）：
- 多轮训练基线（MP）：-0.107% NE
- 随机采样 25% 历史数据（DM-RAND25-RS）：-0.12% NE
- MMR 采样 25% 历史数据（DM-MMR25-RS）：**-0.195% NE**

MMR 比随机采样多 0.07% NE，参数重置比 embedding 缩放多 0.04% NE。

## 关键概念费曼讲解

### 概念一：MMR（最大边际相关性）

想象你在给一个朋友推荐 5 部电影，你有 100 部候选。

**纯相关性策略**：选和他最近看的电影最像的 5 部。结果：5 部都是同一类型的动作片，他看完第一部就腻了。

**纯多样性策略**：选 5 部风格完全不同的。结果：有一部他完全不感兴趣的纪录片，浪费了一个名额。

**MMR 策略**：每次选下一部时，同时考虑"和他口味的相关性"和"和已选电影的差异性"。第一部选最相关的动作片，第二部选相关性次高但和第一部风格不同的喜剧片，以此类推。

Memento 的 MMR 多了一个维度：不只考虑"和用户口味的相关性"，还考虑"和目标广告的相关性"。如果广告是一双跑鞋，那么用户历史里关于运动的记录比关于美食的记录更值得检索，即使用户最近一直在刷美食视频。

### 概念二：灾难性遗忘（Catastrophic Forgetting）

想象一个人学了 5 年钢琴，然后花 3 个月全力学吉他。学完吉他后，他的钢琴技能会退步——不是因为钢琴知识消失了，而是大脑的神经连接被吉他训练重新配置了。

深度神经网络有同样的问题。推荐模型每天在新数据上训练，梯度更新会调整所有参数来拟合新数据。那些只在旧数据里出现的模式（比如"这个用户每年双十一都会买电子产品"），对应的参数区域会被新的梯度覆盖。

Data Memento 的解法类似"定期复习"：从历史里检索出最容易被遗忘的样本，在第二轮训练里重新"温习"。参数重置的作用是：先把 embedding 表清空（防止死记硬背），再用历史+近期数据一起重新学习，迫使模型找到能同时解释新旧数据的通用规律。

### 概念三：仿射调制（Affine Modulation）

想象你在看一张照片，但你戴着有色眼镜。眼镜的颜色（历史上下文 c）会改变你看到的每个像素的颜色（embedding 的每个维度）。

Ember-Affine 就是这个"有色眼镜"：历史上下文 c 通过一个小 MLP 生成每个维度的"色调调整"（γ 是缩放，β 是偏移），把当前用户 embedding 的每个维度都微调一下。

初始化为恒等变换（γ=1, β=0）的好处是：如果历史上下文没有用，模型可以学到"什么都不改"；如果有用，模型会学到"在哪些维度上、往哪个方向调整"。这比直接拼接更有表达力，比 attention 更便宜。

## 餐巾纸速写：范式位移

```
以前的想法：
┌─────────────────────────────────────────────────────┐
│  用户历史 = 一个需要被模型"消化"的长序列              │
│                                                     │
│  解法方向：让模型能处理更长的序列                    │
│  → 高效 Attention（FlashAttention、BigBird）         │
│  → 序列压缩（MIMN、TWIN）                           │
│  → 更大的训练窗口（LastN 线性扩展）                  │
│                                                     │
│  瓶颈：序列越长，噪声越多，计算越贵，遗忘越严重       │
└─────────────────────────────────────────────────────┘

Memento 的想法：
┌─────────────────────────────────────────────────────┐
│  用户历史 = 一个需要被"检索"的文档库                 │
│                                                     │
│  解法方向：让检索系统能找到最相关的历史片段           │
│  → 把历史分块、编码、建索引（类 RAG）                │
│  → 用 MMR 平衡相关性和多样性                        │
│  → 检索结果用于推理增强（Representation Memento）    │
│  → 检索结果用于训练回放（Data Memento）              │
│                                                     │
│  效果：365 天历史持续带来增益，LastN 早已饱和         │
└─────────────────────────────────────────────────────┘

位移的本质：
"让模型处理更多" → "让检索找到更准"
序列建模问题 → 信息检索问题
```

## 博导审稿

**选题眼光**：这个问题是真实的。Meta 广告系统的规模决定了 LastN 的局限不是理论上的，而是每天都在损失真实收益。把 RAG 范式迁移到推荐系统的历史扩展，这个类比是有洞察力的——两者的结构确实同构：都是"从大规模外部知识里检索相关片段来增强当前决策"。

**方法成熟度**：这是一篇工程论文，不是方法论文。MMR 是 1998 年的算法，RAG 是 LLM 领域的成熟范式，Ember-Affine 的仿射调制在 FiLM（2018）里就有了，Ember-Quadratic 的 QNN 引用的是另一篇 KDD'25 论文。Memento 的贡献是**把这些已有工具组合起来，解决一个具体的工业问题，并且做到了生产可用**。这不是坏事，但要清楚这是什么类型的贡献。

**实验诚意**：工业数据集，50B 训练样本，生产 A/B 测试，数字可信。但有几个地方值得追问：（1）MMR 的超参数 α 和 β 是怎么调的？论文给了一个网格搜索的结果，但没有说明调参代价；（2）Ember-Affine 和 Ember-Quadratic 的消融实验显示两者叠加效果最好，但没有分析为什么——是互补还是冗余？（3）Data Memento 只在 CVR 模型上验证，理由是"CTR 模型计算代价太大"，这个局限值得更正面地讨论。

**写作功力**：论文结构清晰，图 1 的架构图直观。但有几处偷懒：Table 2 里 Inference QPS 的负数（-5.28%、-7.00%）表示"每秒处理的请求数减少了"，这是性能下降，但论文把它和 NE 增益放在一起，没有明确说明这是 trade-off；Ember-Quadratic 的参数配置（"Table ??"）明显是占位符，说明论文提交时还没最终确定。

**一句话判决**：**Weak Accept 偏 Accept**。工程贡献扎实，生产验证充分，RAG 类比有洞察力。但方法创新度有限，几个关键 trade-off（QPS 下降、Data Memento 仅限 CVR）处理得不够正面，Ember 架构的理论解释偏弱。

## 启发

**对推荐系统工程师**：这篇论文最有价值的地方不是 MMR 算法本身，而是**把"历史扩展"重新定义为"检索问题"这个框架转换**。一旦接受这个框架，很多工具（向量数据库、ANN 搜索、多样性重排序）就可以直接复用，而不需要从头设计新的序列模型。

**对美团广告/推荐团队**：GenLI 已经在做"用 O(1) 查表替代 pairwise 检索"，Memento 的 Representation Memento 是另一个方向——不是替代检索，而是用 RAG 风格的检索来增强特征。两者可以互补：GenLI 处理中短期行为序列，Memento 处理超长期历史（365 天）。Data Memento 的灾难性遗忘问题在美团的持续训练场景里同样存在，值得关注。

**对我自己**：这篇论文照亮了一个盲区——我之前把"长期用户历史建模"和"序列模型"绑定在一起，没有想到可以用检索范式来解耦。RAG 在 LLM 领域的成功，本质上是"把存储和推理解耦"，这个原则在推荐系统里同样适用。下次遇到"如何处理超长历史"的问题，第一个想到的应该是"能不能先检索再处理"，而不是"能不能让模型处理更长的序列"。

**一个值得追问的问题**：Memento 的 MMR 是无监督的（用余弦相似度，没有端到端训练）。论文最后提到"未来工作是用监督方法改进检索算法"。这个方向很有意思——如果检索器可以和排序模型端到端联合训练，理论上可以学到"什么样的历史片段对当前预测最有帮助"，而不只是"什么样的历史片段和当前请求最相似"。这两者之间的 gap 可能是下一篇论文的缺口。
