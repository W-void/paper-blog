## 缺口：参数量增长不等于表示容量增长

推荐系统的 scaling law 已经被多项工作验证：MetaFormer 架构（Wukong、RankMixer、TokenMixer-Large 等）在堆更多参数、更深的层、更长的行为序列时，AUC 会持续提升。这个结论让工业界充满信心，纷纷投入资源做模型扩容。

但 RankUp 提出了一个更深层的问题：**参数量增长的时候，表示容量（representation capacity）真的在等比例增长吗？**

答案是否定的。先前对 RankMixer 的分析（即 RankElastor 的工作，被 RankUp 引用为 [19]）发现，深层推荐架构的有效秩（effective rank）并不随深度单调增长，而是呈现"阻尼振荡"轨迹——token mixing 之后小幅上升，P-FFN 之后大幅下降，深层的有效秩甚至比浅层还低。这意味着，你花了很多参数扩大了模型，但实际上只在一个低维子空间里工作，大量的表示容量被浪费了。

RankUp 的切入点与 RankElastor 不同。RankElastor 选择改进 token mixing 和 P-FFN 的设计（参数化全混合 + GLU 门控），在架构内部修复 collapse。RankUp 认为，**仅仅改进 token mixing 和 FFN 的设计，是在一个已经受限的表示空间里做文章，治标不治本。真正的问题在于，输入端的表示多样性就已经不够了。** 应该从源头上扩充表示空间的多样性，给模型提供更丰富的原材料。

## 增量：五个机制，从输入端扩充表示多样性

RankUp 提出了五个互补的机制，分别从不同角度扩充输入端的表示多样性：随机置换分割、多 embedding 范式、全局 token 集成、预训练 embedding 交叉集成、任务特定 token 解耦。

这五个机制在微信视频号、公众号、朋友圈三个广告场景全量上线，GMV 分别提升 3.41%、4.81%、2.12%。对于新广告（冷启动场景），GMV 提升更为显著：视频号 +5.83%、公众号 +9.67%、朋友圈 +2.84%。

## 关键概念：有效秩的两种定义

RankUp 使用的有效秩定义是"指数熵秩"（exponential of Shannon entropy of normalized singular values）：

```
erank(H) = exp(−Σ pᵢ ln pᵢ)
其中 pᵢ = σᵢ / Σσⱼ（归一化奇异值）
```

这个定义的范围是 [1, k]（k = min(T, D)），值为 1 表示表示完全坍塌到单一主方向，值为 k 表示信息均匀分布在所有正交方向上。

与 RankElastor 使用的"稳定秩"（stable rank，Frobenius 范数平方除以谱范数平方）相比，指数熵秩对奇异值分布的均匀性更敏感，但两者的方向是一致的：奇异值分布越均匀，两种定义下的有效秩都越高。

## 核心机制：五个互补的反 collapse 策略

### 机制一：随机置换分割（Randomized Permutation Splitting）

传统的 token 分组方式有两种：等距分割（Autosplit，把所有特征的 embedding 拼接后等距切分）和语义分组（把语义相关的特征聚在同一个 token 里）。两种方式都有一个共同问题：高度相关的特征会被聚在同一个 token 里，导致 token 之间的互信息很高，有效秩低。

随机置换分割的做法很简单：在每次训练时，随机打乱稀疏特征的顺序，然后再做等距分割。这样，高度相关的特征会被随机分散到不同的 token 里，减少 token 之间的统计相关性，提升初始表示矩阵的有效秩。

实验验证（Figure 3）：在随机置换策略下，32 个稀疏 token 的有效秩更高且更均匀；在语义分组下，聚集了大量长尾特征的 token（如 Token 12、29、31）有效秩低于 20，而随机置换策略下这些 token 的有效秩都在 40 以上。

互信息分析（Figure 2）：随机置换策略下，稀疏 token 之间的互信息（MI）系统性地低于语义分组，说明 token 之间的统计独立性更高。

### 机制二：多 embedding 范式（Multi-embedding Paradigm）

传统系统用单一 embedding 表把稀疏特征映射到潜在空间，这是一个固定的低维约束。多 embedding 范式用多个独立的 embedding 表（K 个），让同一个特征从多个几何视角被表示。

直觉上：单一 embedding 表相当于只从一个角度拍照，多 embedding 表相当于从多个角度拍照，得到的信息更丰富。这种冗余映射提升了初始表示矩阵 H₀ 的有效秩，为后续的 token mixing 提供更丰富的原材料。

在消融实验中，多 embedding 范式主要改善早期层的表示多样性（Figure 4），防止早期压缩。

### 机制三：全局 token 集成（Global Token Integration）

在 MetaFormer 架构里，每个 token 只编码一个局部特征子集的信息。全局 token 通过聚合函数（MLP 或 FM/DCNv2 等交叉模块）聚合所有特征的信息，然后作为额外的 token 加入序列。

全局 token 的作用是：在 token mixing 时，每个局部 token 都可以通过与全局 token 的交互获得全局上下文，防止深层的有效秩退化（Figure 4 中，去掉全局 token 的变体在深层有效秩从 40 降到 38，而保留全局 token 的变体保持稳定）。

### 机制四：预训练 embedding 交叉集成（Cross Integration of Pre-trained Embeddings）

工业系统里广泛使用预训练的用户和物品 embedding（来自双塔检索模型），这些 embedding 捕捉了粗粒度的语义相似性。但直接把它们拼接到输入里（浅层融合）无法充分利用它们的交互结构。

RankUp 通过元素积（element-wise product）把用户 embedding 和物品 embedding 的交互先验注入到 token 序列：

```
e_cross = Proj(z_u ⊙ z_i)
```

这个交叉 token 被追加到输入序列，显式地把预训练模型的交互先验注入到 token-based 排序架构里。消融实验（Figure 4）显示，去掉交叉 embedding 会导致 Block 0 的有效秩急剧下降，说明外部语义先验对形成丰富的初始化空间至关重要。

### 机制五：任务特定 token 解耦（Task-Specific Token Decoupling）

工业排序系统通常是多任务的（RankUp 的场景是 32 个优化目标）。多任务学习的一个常见问题是梯度干扰：不同任务的梯度方向不一致，会相互抵消，压缩共享表示空间向任务偏置的子空间。

RankUp 为每个任务引入独立的 task token，这些 token 在 backbone 里与共享 token 一起处理，但维护任务特定的表示。最终，task token 和共享 token 的池化结果一起输入到对应的任务塔：

```
y^(k) = Tower^(k)(x_task^(k), Pool(H_L'))
```

互信息分析（Figure 5）显示，有 task token 的 RankUp 在所有聚类粒度下都比没有 task token 的变体有更高的 MI，说明 task token 帮助模型保留了更多任务相关的信息。

## 白话类比：从"大锅饭"到"精准营养"

把推荐模型的表示空间想象成一个营养池，模型需要从这个池子里汲取营养来做预测。

传统的单 embedding + 语义分组就像"大锅饭"：所有特征都被煮在一起，高度相关的特征（比如同一类别的多个特征）会互相稀释，最终营养池里的多样性很低——大家都在喝同一种汤。

RankUp 的五个机制就像"精准营养"：随机置换分割把不同类别的食材随机混合，防止单一食材主导；多 embedding 范式用多种烹饪方式处理同一食材，提取不同层面的营养；全局 token 是一个"综合营养素"，确保每个局部 token 都能获得全局信息；预训练 embedding 交叉集成是"外来食材"，引入其他场景的营养先验；任务 token 解耦是"个性化配餐"，确保不同任务的营养需求不会相互干扰。

## 餐巾纸速写：五个机制的作用层次

```
输入端（Embedding 层）：
┌─────────────────────────────────────────────────────────┐
│  随机置换分割：打破 token 相关性，提升初始有效秩         │
│  多 embedding 范式：扩充初始表示多样性                   │
│  预训练 embedding 交叉集成：注入外部语义先验             │
└─────────────────────────────────────────────────────────┘
                         ↓
Backbone（MetaFormer 层）：
┌─────────────────────────────────────────────────────────┐
│  全局 token：提供全局上下文，防止深层有效秩退化          │
│  SwiGLU FFN：门控乘法结构，抑制 FFN 的有效秩收缩        │
└─────────────────────────────────────────────────────────┘
                         ↓
输出端（任务塔）：
┌─────────────────────────────────────────────────────────┐
│  任务特定 token 解耦：减少多任务梯度干扰                 │
└─────────────────────────────────────────────────────────┘
```

## 实验结果：数字说话

**离线消融（微信视频号广告，Table 1）**

在三个代表性任务（Order、Book、Add Service）上，各机制的 Realtime AUC 提升：

| 机制 | Order | Book | Add Service |
|------|-------|------|-------------|
| 随机置换分割 | +0.06% | +0.06% | +0.08% |
| + 全局 token + 多 embedding | +0.21% | +0.18% | +0.13% |
| + 交叉 embedding | +0.22% | +0.10% | +0.03% |
| + 任务 token | +0.09% | +0.02% | +0.02% |
| **RankUp（全部）** | **+0.41%** | **+0.23%** | **+0.25%** |

**在线 A/B 测试（Table 2，20% 流量，14 天）**

| 场景 | ΔAUC | CTCVR | GMV |
|------|------|-------|-----|
| 微信视频号 | +0.367% | +1.41% | +3.41% |
| 微信公众号 | +0.331% | +0.21% | +4.81% |
| 微信朋友圈 | +0.269% | +0.87% | +2.12% |

**新广告冷启动（Table 3）**

| 场景 | GMV |
|------|-----|
| 微信视频号 | +5.83% |
| 微信公众号 | +9.67% |
| 微信朋友圈 | +2.84% |

新广告的 GMV 提升显著高于整体，说明 RankUp 的丰富表示对冷启动场景特别有效——当行为监督信号有限时，更丰富的初始表示空间能帮助模型更好地捕捉稀疏信号。

**有效秩动态（Figure 4）**

各机制对有效秩的影响有清晰的分工：多 embedding 主要改善早期层的表示多样性；全局 token 稳定深层动态；预训练 embedding 交叉集成主要在 Block 0 贡献；随机置换分割和交叉 embedding 交互进一步增强 token 级多样性，使秩传播更平滑。

**部署规模**

模型参数量从约 10M 扩展到约 100M（每个场景），MFU（Model FLOPs Utilization）达到 23%，在严格的工业延迟约束内全量上线。

## 博导审稿：带了二十年研究生的老教授怎么看

**选题眼光**：从"输入端表示多样性"这个角度切入 collapse 问题，是一个有价值的视角。大多数工作关注的是架构内部的 collapse 机制（token mixing、FFN 的设计），RankUp 提醒我们，问题可能在更上游——特征分组方式、embedding 初始化、多任务干扰等。

**方法成熟度**：五个机制都有清晰的直觉，随机置换分割的互信息分析（Figure 2）和有效秩分析（Figure 3）是有说服力的理论支撑。消融实验设计合理，揭示了各机制的独立贡献和协同效应。

**实验诚意**：完全基于工业数据集（没有公开 benchmark），这是一把双刃剑——可重复性较差，但工业验证的说服力更强。14 天的 A/B 测试和全量上线是最有力的验证。

**潜在质疑**：五个机制的组合是否是最优的？论文没有讨论各机制之间的潜在冲突（比如随机置换分割和多 embedding 范式都在扩充初始多样性，是否存在冗余）。另外，随机置换分割在推理时是否需要固定置换方式，还是每次推理都随机？论文没有明确说明，这对工业部署有实际影响。

**一句话判决**：**Accept**。工业验证充分，GMV 提升显著，五个机制的设计有清晰的直觉和实验支撑。主要局限是缺乏公开 benchmark 验证和各机制之间交互的深入分析。

## 启发：这篇论文照亮了哪些盲区

**第一个盲区：token 分组方式对表示质量有显著影响。** 语义分组是工业系统里的常见做法，但它会把高度相关的特征聚在同一个 token 里，产生低秩的 token 表示。随机置换分割是一个简单但有效的替代方案，值得在更多系统里尝试。

**第二个盲区：冷启动场景对表示多样性更敏感。** RankUp 在新广告上的 GMV 提升（最高 9.67%）显著高于整体（最高 4.81%），说明当行为监督信号稀疏时，更丰富的初始表示空间能带来更大的收益。这对冷启动问题的研究有启发意义。

**第三个盲区：多任务梯度干扰是 collapse 的一个被忽视的来源。** 大多数关于 collapse 的研究关注的是单任务场景，但工业系统通常是多任务的。任务 token 解耦是一个简单的缓解方案，但多任务梯度干扰对有效秩的影响机制还需要更深入的研究。

**对工业实践的直接启示**：如果你的系统正在使用 RankMixer 或类似的 MetaFormer 架构，可以考虑：（1）把语义分组换成随机置换分割，这是一个几乎零成本的改进；（2）引入全局 token，防止深层有效秩退化；（3）如果有预训练 embedding，用元素积的方式注入交互先验，而不是简单拼接；（4）在多任务场景下，为每个任务引入独立的 task token。
