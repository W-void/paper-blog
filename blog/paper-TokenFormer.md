## 缺口：统一建模的代价被忽视了

推荐系统长期以来沿着两条独立的轨道发展：一条是多字段特征交互（Feature Interaction），从 FM、FFM 到 DCNv2、RankMixer，专注于建模稀疏类别特征之间的相关性；另一条是序列行为建模（Sequential Recommendation），从 SASRec、BERT4Rec 到 HSTU，专注于捕捉用户历史行为的时序动态。

工业系统里两者都需要，但传统做法是把它们分开建模，通过异构子网络或后期融合来组合。这带来了大量的工程复杂度：两套参数、两套优化策略、两套 serving 基础设施。

近年来，InterFormer、OneTrans、HyFormer、Kunlun 等工作开始尝试统一建模，但它们往往还是在内部保留了某种形式的分离——混合堆叠、交替组件、或者双路径设计。真正把所有字段和行为序列放在同一个 token 流里、用同一套算子处理的架构，还没有出现。

TokenFormer 想做这件事。但在做之前，它先发现了一个以前没人认真研究过的问题：**把多字段特征和序列特征放在同一个 backbone 里，会导致序列特征的表示质量严重下降。** 这个现象被命名为"序列坍塌传播"（Sequential Collapse Propagation，SCP）。

## 增量：命名一个新的失效模式，并给出双重修复

这篇论文的核心增量是两件事：

第一，**识别并命名了 SCP**。这不只是一个观察，而是一个有理论解释的失效模式：非序列特征的 embedding 因为低基数或频率偏斜，天然就是低秩的；在统一 backbone 里，这些低秩的静态 token 通过共享的注意力算子直接与序列 token 交互，把序列特征的有效秩也拉低了。

第二，**提出了 BFTS + NLIR 的双重修复方案**，在保持统一建模优势（更高的表示判别性）的同时，恢复序列特征的维度鲁棒性。在腾讯广告的在线 A/B 测试中，TokenFormer 实现了 4.03% 的 GMV 提升，同时 serving 吞吐量提升 5.5 倍。

## 关键概念：SCP 是什么，为什么它是统一建模的核心障碍

SCP 的直觉是这样的：想象你有一个班级，大部分同学（序列 token）都很活跃，有丰富的个性（高维表示）；但班里有几个沉默的同学（静态特征 token），他们的表达非常单调（低秩 embedding）。如果你把所有人放在同一个教室里，让他们互相影响，那些沉默的同学会把整个班级的"表达多样性"拉低——不是因为他们主动破坏，而是因为共享的交互机制会把他们的低秩特性传播给其他人。

用数学语言说：非序列特征（用户画像、上下文特征等）往往是低基数的，它们的 embedding 矩阵的奇异值高度集中在少数几个方向，有效秩很低。在统一 Transformer 里，注意力机制让序列 token 和静态 token 充分交互，这种交互会把静态特征的低秩结构"传播"到序列特征的表示里，导致序列特征的有效秩也随着层数增加而持续下降。

TokenFormer 的 Figure 1 直观展示了这个张力：纯序列 Transformer（绿色）的序列特征有效秩较高，但判别性（互信息）较低；朴素统一 Transformer（蓝色）的判别性显著提升，但有效秩急剧下降，奇异值谱衰减更陡峭。TokenFormer（橙色）同时实现了高判别性和高有效秩。

## 核心机制：BFTS 和 NLIR

### 统一 token 流

TokenFormer 把所有输入——非序列字段特征 F、序列行为 token T、目标特征 V——拼接成一个统一的 token 流，用同一套 Unified Interaction Block（UIB）处理。没有显式的类型 embedding，而是用 RoPE（旋转位置编码）注入相对位置信息：静态字段映射到位置 0，序列 token 按时序排列，目标 token 映射到最大位置。

这种设计让模型可以同时建模六种交互类型：F↔F（字段间相关性）、T↔T（序列内时序依赖）、V↔V（目标特征相关性）、T↔V（行为-目标相关性）、F↔T（字段-序列依赖）、F↔V（字段-目标相关性）。

### BFTS：底层全注意力，顶层滑动窗口

BFTS 的核心思想是：**不同层应该有不同的注意力范围，而不是所有层都用同样的全因果注意力。**

浅层（前 l_f 层）用全因果注意力，让静态字段 token 和序列 token 充分交互，建立全局跨域上下文。这是必要的——如果浅层就限制注意力范围，模型会失去整合异构特征的能力。

深层（后 l_s 层）切换到收缩窗口的滑动窗口注意力（SWA），窗口大小从 w_1 逐层收缩到 w_{l_s}（w_{l_s} < w_{l_s-1} < ... < w_1）。更重要的是，深层完全丢弃对非序列 token 位置的注意力——一旦静态特征的信息在浅层被充分整合进序列表示，深层就不再需要回头看这些静态 token，这样可以防止低秩静态噪声在深层继续污染序列特征。

实验验证了这个设计的必要性：把 SWA 均匀应用到所有层（4S 配置）会导致 AUC 灾难性下降（-36.35‰），因为浅层的全局交互被截断了；而 BFTS（2F2S 配置）在提升 AUC 的同时还减少了 GFLOPs。

### NLIR：乘法门控保持秩丰富性

NLIR 在注意力输出上施加一个单侧非线性乘法调制：

```
G^(l) = X^(l) W_g^(l)                    # 门投影
Ĩ^(l) = σ(G^(l)) ⊙ A^(l)               # sigmoid 门 × 注意力输出
I^(l) = X^(l) + Ĩ^(l)                   # 残差相加
```

这里 σ 是 sigmoid 函数，⊙ 是逐元素乘法。这个操作把高阶非线性引入了 token mixing 过程，理论上可以保持表示的秩丰富性——乘法交互产生二阶特征，防止表示被压缩到少数几个主方向。

NLIR 之后接 SwiGLU FFN，进一步用门控乘法结构处理特征。

### 残差连接的几何效应

TokenFormer 的分析还揭示了残差连接的一个有趣几何效应：注意力后的残差连接（I^(l) = X^(l) + Ĩ^(l)）系统性地提升有效秩（erank(I^(l)) > erank(Ĩ^(l))），而 FFN 后的残差连接（X^(l+1) = I^(l) + H^(l)）则把有效秩拉回到一个中间水平（erank(X^(l+1)) 介于 erank(I^(l)) 和 erank(H^(l)) 之间）。这说明残差连接不只是优化稳定性的工具，它还在主动调节表示的维度多样性。

## 白话类比：两个班级合并的故事

把序列 token 想象成一个活跃的班级，每个同学都有丰富的个性（高维表示）。把静态特征 token 想象成另一个沉默的班级，同学们的表达都很单调（低秩 embedding）。

朴素统一建模就是把两个班级合并，让所有人坐在同一个教室里上课。好处是显而易见的：活跃班级的同学可以从沉默班级的同学那里获得一些背景信息（判别性提升）。但问题是，沉默班级的同学会把整个教室的"表达多样性"拉低——老师（注意力机制）会花很多时间关注那些沉默的同学，而这些关注并没有带来有价值的信息，反而干扰了活跃同学之间的互动。

BFTS 的解决方案是：**前几节课（浅层）让两个班级充分交流，建立基本的相互了解；后几节课（深层）让活跃班级专注于自己的讨论，沉默班级的同学可以旁听但不参与互动。** 这样既保留了跨班级信息整合的好处，又防止了沉默班级对活跃班级的持续干扰。

NLIR 的解决方案是：**在每次交流之后，给活跃班级的同学一个"过滤器"（sigmoid 门），让他们自己决定从这次交流中保留哪些信息，丢弃哪些噪声。** 这个过滤器是乘法的，而不是加法的，所以它能产生更丰富的高阶信息，而不只是简单地选择或丢弃。

## 餐巾纸速写：SCP 的传播路径与阻断

```
统一建模的信息流（朴素 Transformer）：
┌─────────────────────────────────────────────────────────┐
│  静态特征 F（低秩 embedding）                            │
│       ↓ 注意力交互（所有层）                             │
│  序列特征 T（高维 embedding）                            │
│       ↓ 有效秩被持续拉低（SCP）                          │
│  深层序列表示（低秩，判别性受损）                        │
└─────────────────────────────────────────────────────────┘

TokenFormer 的阻断策略：
┌─────────────────────────────────────────────────────────┐
│  浅层（BFTS 全注意力）：F 和 T 充分交互，建立全局上下文  │
│       ↓ 静态信息被整合进序列表示                         │
│  深层（BFTS 滑动窗口 + 丢弃 F）：T 专注局部时序精炼      │
│       ↓ NLIR 乘法门控保持秩丰富性                        │
│  深层序列表示（高秩，高判别性）                          │
└─────────────────────────────────────────────────────────┘
```

## 实验结果：数字说话

**公开数据集（KuaiRand-27K）**

TokenFormer 在 User-Centric 设置下，Tiny 版本就超过 Transformer baseline 5.00‰ AUC，超过强 baseline HSTU-Ultra 2.05‰。随着模型规模从 Tiny（0.48M 参数）扩展到 Large（10.14M 参数），AUC 持续提升（+5.00‰ → +8.15‰），展现出清晰的 scaling law。

**在线 A/B 测试（腾讯广告，微信视频号）**

相比生产基线（高度优化的 DLRM 架构），TokenFormer 实现了 4.03% 的 GMV 提升。Serving 吞吐量从 126 QPS 提升到 695 QPS（5.5 倍加速），来自 BFTS 的稀疏化和解耦 serving 策略（用户侧 token 只编码一次，压缩成 N 个 summary token 后与候选广告组合）。

**消融实验**

单独加 NLIR：+4.87‰ AUC。单独加 BFTS：+4.91‰ AUC。两者结合（TokenFormer）：+5.00‰ AUC（Tiny 版本）。两个模块有协同效应，但也各自独立有效。

在线消融：纯全注意力 TokenFormer 相比生产基线 -0.16%；加 BFTS 后 +0.14%；再加 NLIR 后 +0.22%。

**有效秩分析**

Figure 4 展示了三个模型变体（Vanilla Transformer、+BFTS、+NLIR）的逐层有效秩轨迹。Vanilla Transformer 的有效秩随层数增加急剧下降；+BFTS 和 +NLIR 都能独立缓解这种下降；两者结合（TokenFormer）的有效秩轨迹最为平稳。

## 博导审稿：带了二十年研究生的老教授怎么看

**选题眼光**：SCP 这个概念的命名和系统化研究是这篇论文最大的贡献。统一建模是推荐系统的长期追求，但"统一的代价"一直没有被认真研究。把这个代价量化为有效秩的下降，并给出可操作的修复方案，是有价值的工作。

**方法成熟度**：BFTS 的设计有清晰的直觉支撑，消融实验也验证了"浅层全注意力 + 深层滑动窗口"的必要性（4S 配置的灾难性失败是一个有力的反例）。NLIR 的设计借鉴了 HSTU 等工作的乘法门控思路，理论基础扎实。两个模块的协同效应在实验中得到了验证。

**实验诚意**：公开数据集 + 工业数据集的双重验证，离线 + 在线的双重验证，这是工业推荐论文的标准配置，做得比较完整。有效秩的逐层分析（Figure 4、5）是亮点，直观展示了 SCP 的传播路径和 TokenFormer 的修复效果。

**潜在质疑**：BFTS 的超参数（l_f 和 l_s 的比例，窗口大小 w）对性能有显著影响，但论文只在 KuaiRand-27K 上做了敏感性分析，没有讨论这些超参数在不同场景下的迁移性。另外，TokenFormer 的统一建模假设所有字段和序列都可以用同一套 RoPE 位置编码来区分，这个假设在特征字段非常多（工业系统里可能有数百个字段）时是否还成立，需要更多验证。

**一句话判决**：**Accept**。SCP 的识别和命名是有价值的理论贡献，BFTS + NLIR 的工程方案有清晰的直觉和实验支撑，在线 GMV 提升和 serving 加速是有说服力的工业验证。

## 启发：这篇论文照亮了哪些盲区

**第一个盲区：统一建模不是"免费的午餐"。** 把多字段特征和序列特征放在同一个 backbone 里，会带来判别性的提升，但也会带来 SCP 的风险。在设计统一架构时，需要有意识地评估和对抗 SCP，而不是假设统一建模自然会带来更好的结果。

**第二个盲区：注意力范围的层次化设计。** BFTS 的核心洞察是，不同层的注意力应该有不同的范围——浅层需要全局视野来整合异构特征，深层需要局部聚焦来精炼时序结构。这个思路不只适用于统一建模，在任何需要处理异构 token 的场景（如多模态推荐、跨域推荐）都可能有价值。

**第三个盲区：残差连接的几何效应。** TokenFormer 的分析揭示了注意力残差和 FFN 残差对有效秩的不同影响（前者提升，后者拉回中间水平）。这个发现对理解深层 Transformer 的表示动态有启发意义，值得在更多场景下验证。

**对工业实践的直接启示**：如果你的系统正在考虑把多字段特征和序列特征统一建模，TokenFormer 的 BFTS + NLIR 是一个经过工业验证的方案。特别是 BFTS 的 serving 优化（解耦用户侧编码）带来的 5.5 倍吞吐量提升，在工业部署中是非常有价值的。
